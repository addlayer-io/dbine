# Code quality

While you write in the query editor, DBine flags what usually causes
problems: slow queries, unexpected results or changes that affect more rows
than you think. The analysis is **text-only**: it doesn't query the database
or touch the connection.

## Where it is

- **In the editor:** problems are marked in the gutter and underlined.
  Hovering a mark shows the message, why it matters and how to fix it, and
  the rule id.
- **View problems:** the editor toolbar button (with the count, for example
  **3 problems**, or **No problems**) opens the **Script problems** list, with
  each one's line. **Configure rules…** opens the settings.
- **Settings › Code quality:** the **Check the code as I write** switch and
  one switch per rule. **Turn all on** turns back on the ones you turned off.

If the analysis is off, or the tab's connection can't be analyzed (for
example, a driver that isn't installed), the editor marks nothing and the
**View problems** button doesn't appear.

## What is flagged

Each problem has a **severity**:

- **Error:** almost always a human mistake, such as a write without a filter.
- **Warning:** usually gives slow or unexpected results.
- **Suggestion:** a style or maintenance improvement.

What's inside a quoted string, a comment or a quoted name is **never
flagged**: each engine has its own lexical analyzer that recognizes them.

The switches are stored in DBine's settings, on this machine: `lint.enabled`
and the `lint.disabled` list of turned-off rules.

## Rules

Each engine gets the rules of its family. The groups are the ones in the
settings.

### All SQL engines

| Rule | Severity | Detects |
|---|---|---|
| `select-star` | Suggestion | `SELECT *`. Also in CQL. |
| `dml-without-where` | Error | `UPDATE` or `DELETE` without `WHERE`. Also in CQL. |
| `not-in-subquery` | Warning | `NOT IN (subquery)`: a single `NULL` in the subquery leaves the result empty. |
| `leading-wildcard` | Warning | A `LIKE` pattern that starts with a wildcard, which can't use an index. Also in CQL and in the search consoles. |
| `function-on-column` | Warning | A function applied to a column in the `WHERE`, which prevents using its index. |
| `equals-null` | Warning | `= NULL` or `<> NULL`, which is never true. |
| `order-by-ordinal` | Suggestion | `ORDER BY 2`: orders by the column's position. |
| `order-by-random` | Warning | A random order (`RANDOM()`, `NEWID()`…) that sorts the whole table. |
| `implicit-cross-join` | Warning | A `FROM` table separated by a comma and with no condition relating it: Cartesian product. |
| `insert-without-columns` | Warning | `INSERT` without a column list. |
| `distinct-group-by` | Suggestion | `DISTINCT` together with `GROUP BY`. |
| `union-distinct` | Suggestion | `UNION` where `UNION ALL` would avoid sorting or building a hash. |

### SQL Server, Azure SQL, Fabric and Sybase

| Rule | Severity | Detects |
|---|---|---|
| `nolock` | Warning | `NOLOCK` or `READ UNCOMMITTED`: reads uncommitted data. |
| `cursor` | Suggestion | Cursors, which process one row at a time. |
| `set-rowcount` | Warning | `SET ROWCOUNT`, which stays active in the session and is deprecated for `INSERT`, `UPDATE` and `DELETE`. |
| `global-identity` | Warning | `@@IDENTITY`, which can return the identity generated by a trigger. |
| `sp-prefix` | Warning | Procedures with the `sp_` prefix, the one for system procedures. |
| `set-nocount` | Suggestion | A procedure without `SET NOCOUNT ON`. |

### PostgreSQL family

| Rule | Severity | Detects |
|---|---|---|
| `for-update-wait` | Suggestion | `FOR UPDATE` that waits for the lock, without `SKIP LOCKED` or `NOWAIT`. Also in MySQL and Oracle. |
| `serial-identity` | Suggestion | `serial` instead of `GENERATED … AS IDENTITY`. |

### MySQL family

| Rule | Severity | Detects |
|---|---|---|
| `for-update-wait` | Suggestion | See above. |
| `group-by-nonaggregated` | Warning | A column that is neither in the `GROUP BY` nor inside an aggregate function. |

### Oracle

| Rule | Severity | Detects |
|---|---|---|
| `for-update-wait` | Suggestion | See above (in Oracle `WAIT n` is also suggested). |
| `rownum-order-by` | Warning | `ROWNUM` with `ORDER BY` in the same block: it's cut before sorting. |
| `outer-join-plus` | Suggestion | The `(+)` outer join syntax. |

### InfluxDB (InfluxQL and SQL)

| Rule | Severity | Detects |
|---|---|---|
| `delete-without-time` | Warning | `DELETE` without a condition on `time`. |
| `drop-series` | Warning | `DROP SERIES` or `DROP MEASUREMENT`, which delete all the history. |

### Cassandra, ScyllaDB and Amazon Keyspaces

In addition to `select-star`, `dml-without-where` and `leading-wildcard`:

| Rule | Severity | Detects |
|---|---|---|
| `allow-filtering` | Warning | `ALLOW FILTERING`, which scans the partitions. |
| `no-partition-key` | Warning | A `SELECT` without `WHERE`: it reads all the partitions. |
| `batch-partitions` | Suggestion | A `BATCH` that writes to several tables or partitions. |

### MongoDB, FerretDB and DocumentDB

| Rule | Severity | Detects |
|---|---|---|
| `write-all` | Error | A write without a filter. Also in the search consoles and in etcd. |
| `where-operator` | Warning | `$where`, which runs JavaScript per document. |
| `unanchored-regex` | Warning | A regular expression that doesn't start with `^`. Also in CouchDB. |
| `read-all` | Suggestion | A read without a filter. Also in CouchDB and etcd. |

### CouchDB

`unanchored-regex` and `read-all`.

### Elasticsearch, OpenSearch and Solr

`leading-wildcard` and `write-all`.

### Redis, Valkey and Dragonfly

| Rule | Severity | Detects |
|---|---|---|
| `keys-command` | Warning | `KEYS`, which scans all the keys and blocks the server. |
| `flush` | Error | `FLUSHALL` or `FLUSHDB`. |
| `big-read` | Suggestion | A full read of a key (for example `HGETALL`, `SMEMBERS`). |

### etcd

`write-all` and `read-all`.

### Neo4j, Memgraph and Neptune

| Rule | Severity | Detects |
|---|---|---|
| `match-without-label` | Warning | A `MATCH` without a label or properties: it scans all the nodes. |
| `cartesian-product` | Warning | Disconnected patterns, separated by a comma. |
| `detach-delete-all` | Error | `DETACH DELETE` without `WHERE`. |

The rest of the engines (for example InfluxDB 2 with Flux) have no rules.
Which engine gets which group is in
[`engine-support.md`](engine-support.md#code-quality).

## Contract

Code quality **adds no methods to the drivers**. It relies on `DriverInfo`
(`language`, `dialect`, `id`) and on `Driver::script_dialect()`, which already
existed, to choose the analyzer and the rules.

- The analysis is in `src-tauri/src/lint/` (one lexical analyzer per family
  and the rules). Each rule's texts live in the interface
  (`lint:rules.<id>`): a finding carries the rule, its range and the values
  the message shows.
- Commands: `lint_script` (takes `connectionId` and `sql`; returns the
  findings with positions in UTF-16 indices and the line) and `lint_rules`
  (the list of rules for the settings). See
  [`api-commands.md`](api-commands.md).

### Unknown names (all SQL and CQL engines)

The backend doesn't analyze these two rules: the editor compares the text
with the database objects the explorer knows about. Detail and cases that
aren't flagged in
[Query editor](query-editor.md#unknown-names).

| Rule | Severity | Detects |
|---|---|---|
| `unknown-table` | Warning | A table in `FROM`, `JOIN`, `UPDATE` or `INSERT INTO` that doesn't exist in the tab's database. |
| `unknown-column` | Warning | A qualified column or one from an `INSERT` list that the table doesn't have (only with the columns already loaded). |
