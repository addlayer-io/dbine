# 変更履歴

## [1.7.1] - 2026-11-25

### 新機能
- **失敗したクエリを「AIで分析」:** クエリのエラーの横にあるボタンで、失敗した理由をAI(アシスタントで選択したもの)に尋ねられます。送信されるのは実行したSQL、エラー、データベースの構造だけで、行は一切送られず、クリックしたときにのみ送信されます。処理中はモデル、経過秒数、「キャンセル」ボタンが表示され、プロバイダーが対応していれば説明がストリーミングで表示されます。修正後のクエリはエディターに提案として表示され、削除されたテキストは赤、追加されたテキストは緑で示され、各変更とすべての変更に対して「承認」と「却下」を選べます。承認するまでテキストは変わらず、「元に戻す」を1回行えば元に戻り、何も実行されません。AIを許可していない会社の接続では、引き続きAIが拒否されます。
- **接続をまたぐリネージ:** リネージは、データベースの外にあるソースを、それを保持する接続までたどります。SQL Server、Databricks、PostgreSQLなどのエンジンのテーブルを読み取るPower BIのテーブルでは、そのソースが灰色のカードで表示されます。クリックすると、指している保存済みの接続が見つかり(1回だけ確認することも、サーバーとデータベースが入力済みの状態で**ソースから接続を作成**することもできます)、カードが実際のテーブルに変わり、それが使用するものがレベルごとに表示されます。逆方向では、**他の接続を含める**で、あるオブジェクトを読み取るPower BIのテーブルと、そこから、それを読み取るセマンティックモデル、レポート、ダッシュボードが表示され、各カードの接続が示されます。DBine Enterpriseでは、会社のサーバーがソースを各ユーザーが使用できる接続に解決し、**他の接続を含める**はEnterpriseの接続からも使えます。
- **リネージをたどるのにエクスプローラーの接続は不要:** 接続が1つあるソースのカードをクリックすると、すぐにその接続へ移動します。接続がない場合は、パネルがその場でユーザー名とパスワードを求め(読み取り専用。**このコンピューターに記憶する**でパスワードをシステムのキーチェーンに保存できます)、リネージが自動的に接続し、サイドバーには何も追加されません。**設定 › リネージのソース**にはこれらの接続が一覧表示され、(記憶したパスワードとともに)削除するか、通常の接続として**エクスプローラーに追加**できます。
- **種類でリネージを絞り込み:** データベースまたはPower BIモデルのリネージには**種類**リストがあり、種類ごとにチェックボックスと件数が表示されます。テーブル、ビュー、メジャー、プロシージャ、データベースのその他のオブジェクトに加え、それぞれ個別に、ジョブ(サーバーとDatabricksのもの)、ノートブック、パイプライン、クエリ、レポート、ダッシュボード、ファイル、その他のソースがあります。種類のチェックを外すと、そのカードと線が非表示になります。

### 改善
- **「依存関係を表示…」が高速化:** PostgreSQL、Oracle、SAP HANA、MySQL、MariaDB、ClickHouse、Db2、Firebird、Power BIでは、テーブル、ビュー、ルーチン、シーケンス、列に依存するものを、データベース内のすべてのビュー、ルーチン、トリガーの定義を1つずつ読み取る代わりに、エンジン自身の依存関係カタログからそのオブジェクトで絞り込んで読み取ります。待ち時間はルーチンの数に比例して増えなくなりました。カタログで確認できないコード(動的SQL、手続き型の本体)は、テキストにその名前が含まれる場合にのみ読み取ります。Power BIでは、そのオブジェクトを参照する依存関係の行だけを要求します。サーバーがカタログを拒否した場合は、これまでどおり定義を読み取り、その旨を表示します。
- **依存関係とリネージのサーバーからの読み取りを削減:** 外部キーのないテーブルの参照では、それを示すためにデータベース全体の構造を読み取らなくなり、スケジュールされたジョブを持つデータベースのリネージでは、サーバーのデータベース一覧をジョブごとではなく1回だけ取得します。
- **巨大なPower BIモデルのリネージを読み取りながら表示:** エラーで終わっていた1回の長い待ち時間の代わりに、モデルのリネージを短いステップで読み取ります。テーブルとソース、リレーションシップ、メジャーと列の依存関係(バッチ単位)、最後にレポートとダッシュボードの順です。ダイアグラムは最初のステップで表示され、各ステップの終了ごとに再描画され、すべてそろうまで進行状況のラベルと「部分的なリネージ」の通知が表示されます。読み取った内容は各ステップの後に保存されるため、次回は中断したところから続きます。失敗したステップは1回再試行され、その後そのステップだけを再読み取りするボタンが表示され、残りの処理は続行されます。
- **リネージが解決済みの状態で開く:** DBineは各データベースのリネージ(Power BIでは各モデルのソース)をエクスプローラーのキャッシュの隣に保持し、接続後にバックグラウンドで1データベースずつ読み取ります。初めて開くときも待つ必要はありません。リネージを開くと保存済みのものがすぐに表示され、読み取りからの経過時間も示され、バックグラウンドで更新されます。**設定 › 一般**には、事前計算をオフにするスイッチと、保存済みのリネージを消去するボタンがあります。
- **大規模なPower BIテナントでのリネージ検索が高速化:** Power BIモデル全体でオブジェクトを読み取っているものを探す検索では、各モデルのソースだけを制限時間付きで読み取り、同時に読み取るモデル数は**設定**で変更できます(1〜16、既定は4)。Power BIの管理者の場合、DBineはPower BIの管理者スキャナーAPIにも各モデルの読み取り元を問い合わせ、検索元の接続を読み取れるモデルだけを開きます。お使いのユーザーで利用できない場合は、モデルを1つずつ読み取り、その旨を表示します。
- **Power BIの管理APIはサインイン時ではなく必要時に要求:** スキャナーには管理者だけが承認できる読み取り専用の追加権限が必要なため、サインインには含まれなくなり、これが原因でブロックされる人はいません。アカウントにすでに権限がある場合、DBineは通知なしに使用します。そうでない場合、検索はモデルを1つずつ読み取り、必要なものを表示します。**設定 › 一般**ではスイッチでオフにでき、**管理 API を承認…**(Power BIの接続ごとに1つ)でブラウザーから権限を1回だけ要求できます。管理者でない場合は、Entraの拒否がわかりやすいメッセージで表示されます。
- **リネージを開くときの待ち時間を設定可能に:** 非常に大きなモデルやデータベースのリネージ、依存先、参照を開くとき、5分であきらめなくなりました。上限は既定で15分で、**設定**で延長できます。Power BIモデルごとの待ち時間(既定3分)と検索の継続時間(15分)も同様に延長できます。
- **リネージ内のリンクをブラウザーで開く:** リネージの詳細パネルにあるWebアドレス(Databricksのジョブ、ノートブック、パイプライン、クエリ、ダッシュボード、Power BIのレポート)がリンクになり、クリックするとブラウザーで開きます。DBineが接続できないDatabricksのジョブやノートブックにも、そのページへのリンクが表示されます。

### 修正
- **DBine Enterprise: 「データを表示」と接続が「接続中…」で止まらなくなりました:** 会社の接続でテーブルのデータを開くと、その接続のDBine Bastionへのチャネルがフリーズすることがあり、その後のすべての操作(接続、データベースの一覧表示、クエリの実行)が永久に待機していました。チャネルが応答を続けるようになりました。Bastionが30秒以内に応答しない接続はメッセージとともに失敗し、次回の試行では新しいチャネルが開かれます。また、エクスプローラーが会社の接続が接続済みであることを毎分忘れることがなくなり、再接続中に読み込み済みのデータベースとテーブルが「接続中…」の裏に隠れることもなくなりました。
- **DBine Enterprise: 会社があなたのアクセスを終了すると、関連するものは何も残りません:** アクセスが取り消されると、DBineは会社との接続を切断し、そのセッションを閉じ、関連するローカルデータ(接続、保存済みクエリ、履歴、エクスプローラーのキャッシュ、リネージ、結果、それを使用したAIの会話)を削除し、その理由を通知します。これは、アクセスの取り消し、サインインの拒否、別のユーザーがコンピューターにサインインしたとき、およびアクセスを24時間確認できなかったときに、直ちに行われます。
- **DBine Enterprise: アクセスの一部を失った場合は、その部分だけが削除されます:** 会社がデータベース、接続、またはグループのアクセスを取り上げても、残りは保持される場合、DBineは失った分のセッションを閉じ、それに関するローカルデータ(エクスプローラーのキャッシュ、リネージ、保存済みクエリ、履歴、タブ、それに関するAIの会話)だけを削除し、他の接続やデータベースには触れません。これは数秒以内に行われ、DBineが通知を受け取れなかった場合は次回の同期で修正されます。アクセス全体を失った場合は、これまでどおりすべて削除されます。
- **DBine Enterpriseがエクスプローラーに戻りました:** **Enterprise**ボタンとそのサインインが、すべてのビルドで再び表示されます。
- **Power BIモデルのリネージが設定した待ち時間を守るように:** 分割して読み取る際、**設定**の値にかかわらず90秒であきらめていました(画面には15分と表示されていましたが、アプリは90秒を使用し、3分を超えることはありませんでした)。現在は、各読み取りが設定の時間(既定は15分)待機します。
- **リネージを開くとき、同じデータベースの別の読み取りを待たなくなりました:** DBineがバックグラウンドで読み取っている間(またはスキーマ比較やモデル横断の検索が読み取っている間)にデータベースまたはPower BIモデルのリネージを開くと、その読み取りの終了を待ち、「接続は構造の読み取り中でまだ使用中です」で失敗することがありました。同じデータベースの長時間の読み取りが並行して実行されるようになり(最大3つ同時)、大きなPower BIモデルの依存関係は3バッチずつ読み取られます。
- **Power BIの検索が200モデルで止まらなくなりました:** リネージ検索とバックグラウンドのウォームアップは、ワークスペースのすべてのモデルを読み取ります。
- **Oracle: 影響を確認する名前変更で、オブジェクト自身を依存先として表示しなくなりました:** オブジェクトがセッション自身のスキーマのものである場合、Oracleの依存先リスト(名前変更の影響リストを含む)に、そのオブジェクト自身が依存先の1つとして表示されていました。今後は表示されません。
- **SQLの整形に失敗してもエディターが覆われなくなりました:** フォーマッターがクエリを解析できなかったとき、そのメッセージが期待されるすべてのトークンを列挙してウィンドウを埋め尽くし、閉じる手段がありませんでした。現在は、失敗した位置と期待されなかったものだけを表示し、ウィンドウに収まり、閉じるボタンがあります。SQLは変更されません。
- **リネージのソースをたどる操作が安全に:** リネージのソースからDBineが作成する接続は、パスワードの入力中に暗号化なしや未検証の状態になるのではなく、新しい接続と同様に検証済みのTLSを使用します。ファイルやパス(Access、dBase、SQLite、DuckDB、ODBC、ネットワーク共有)であるソースや、DBineが認識しないエンジンは、リネージから開かれなくなりました。手動で追加し、ご自身で確認してください。
- **2つのWebライブラリを修正版に更新:** DBineがWebアドレスとCookieの読み取りに使用するライブラリを更新し、影響の小さい2件のセキュリティ勧告を修正しました。

## [1.7.0] - 2026-11-21

### 新機能
- **ベクトル（エンベディング）：** DBine は、ベクトルを保存するエンジン（pgvector を使う PostgreSQL、MySQL、Oracle、SQL Server、Snowflake、Elasticsearch、OpenSearch、Redis とその関連製品、MongoDB、Cassandra、DuckDB、libSQL、Neo4j など）で、ベクトルの読み取り、編集、インデックス作成、比較、移動、検索を行います。ベクトルのセルには先頭の数値と次元数のバッジが表示され、セルビューアーには要素の型、ノルム、最小値、最大値が表示されます。編集内容は、サーバーに届く前に列の次元数と要素の範囲に照らして検証されます。各エンジンは、それぞれ独自の型、インデックスのアルゴリズム、距離を保持します。
- **デザイナーとエクスプローラーでのベクトルインデックス：** テーブルデザイナーでベクトルインデックス（HNSW、IVFFlat、DiskANN など各エンジンが提供するもの）を距離と設定とともに作成・編集でき、エクスプローラーでは「インデックス」タブに一覧表示されます。Redis、Valkey、Dragonfly は、キーデータベース内の専用フォルダーに検索インデックスを一覧表示し、メニューにそのフィールドとテンプレートを表示して、削除もできます。
- **比較、転送、変換でのベクトル：** スキーマの比較と同期、データの比較、転送、クローン、移行、サブセット、テストデータ、マスキング、スキーマ変換で、ベクトルとそのインデックスがエンジン間で引き継がれます。移行先が何かを正確に保持できない場合は、変換レポートに何が変わったか、または省略されたかとその理由が記載されます。たとえば、バイナリベクトルの Hamming インデックスが libSQL ではコサインとして保持される場合や、Cosmos DB には幅が広すぎる flat インデックスが量子化インデックスになる場合です。
- **ノートブック、エクスポート、データベースドキュメント、アシスタントでのベクトル：** DataFrame SQL、エクスポート、データベースドキュメント、AI アシスタント、MCP ツールがベクトル列とベクトルインデックスに対応します。エディターは各エンジンのベクトル関数と演算子を補完します。
- **エクスプローラーのフィルターは、開いていないものやコードの中も検索：** 入力に合わせて、フィルターは開いているデータベースの中からテキストを探します。まずエクスプローラーが前回の内容として記憶しているもの（即時）、次にサーバー上の名前を対象にし、一致した項目を手動で開かなくてもそれぞれのフォルダー（テーブル、ビュー…）に表示します。**</>** をオンにすると、ビュー、プロシージャ、関数、トリガー、そして Power BI のメジャーとテーブル（その Power Query と DAX）といった定義の中も検索します。これらの一致には **コード** のタグと、テキストがある行が表示されます。Power BI の**データベース内を検索…**は、テーブルの Power Query と計算列も検索するようになりました。BigQuery ではメタデータのクエリごとに課金されるため、フィルターは **Enter** を押したときだけサーバーに問い合わせます。
- **リネージと、オブジェクトが使用するもの：** **依存関係を表示…**は、オブジェクト自身が使用するものも一覧表示するようになりました。ビューが読み取るテーブルとビュー、プロシージャが呼び出すルーチン、外部キーの参照先テーブル、データベース外のソースです。**リネージを表示…**は両方向を図として描画し、左側に使用先、右側にそれを使用するものを表示し、各カードはどちらの方向にももう 1 段階展開できます。実線はエンジンのカタログから、破線はコードの読み取りから得たもので、クリックすると他方のオブジェクトの名前が出てくる行が表示されます。依存関係カタログを持つエンジンは、それぞれ自分のカタログを読み取ります。対象は SQL Server、Oracle、PostgreSQL とその系列、MySQL 8、Db2、SAP HANA、Firebird、ClickHouse、Snowflake、MongoDB のビュー、Cassandra です。Databricks は Unity Catalog のリネージを、Power BI は `INFO.CALCDEPENDENCY` と各テーブルの Power Query のソースを使用します。リンクサーバー、データベースリンク、外部テーブル、他のデータベース、Power BI のデータソースは、データベース外のソースとして表示されます。サーバーのジョブも含まれます。SQL Server Agent のジョブ、pg_cron と pgAgent のジョブ、`DBMS_SCHEDULER` のジョブ、MySQL のイベント、そのステップがオブジェクトを実行するその他のスケジュール済みジョブがその右側に表示されるため、リネージは、テーブルから、それを使用するビューやプロシージャを経て、それらを実行するジョブまでつながります。ジョブ自体のリネージは、**スケジュール › サーバー**から開くと、そのステップが使用するものを表示します。
- **データベース全体のリネージ：** データベース、スキーマ、フォルダー（テーブル、ビュー…）、または Power BI モデルを右クリック › **リネージを表示…**で、そのすべてのオブジェクトとすべての依存関係を、データベース外のソースやサーバーのジョブとともに 1 つの図に描画します。オブジェクトが約 200 を超える場合は、スキーマごとに 1 枚のカードを持つ概要として開き、ダブルクリックでそのスキーマを開きます。種類とテキストで絞り込めるほか、確認済みの線だけ、依存関係を持つオブジェクトだけに絞り込めます。リレーション（外部キーと Power BI モデルのリレーションシップ）はリネージと並行して扱われ、スイッチでリネージと一緒に表示するか、リネージだけにするかを切り替えられます。データベース全体のビューでは、最初は非表示です。SQL Server、PostgreSQL とそのカタログを共有するエンジン、Oracle、Db2、SAP HANA、MySQL と MariaDB、ClickHouse、Snowflake、Databricks、MongoDB のビュー、Power BI のモデル全体は、それぞれのカタログから読み取り、タブを開いたときに読み込みます。それ以外のエンジンでは、スキャンの内容と**分析**ボタンが表示されます。すべての定義を読み取るためです。
- **結果内を検索：** 結果のグリッドで ⌘F（Ctrl+F）を押すか、結果バーの虫眼鏡をクリックすると、画面に表示されている行や列だけでなく、読み込まれたすべての行と列を検索し、一致した箇所をハイライトします。一致のある列とその件数を一覧表示し（クリックすると検索をその列に限定）、Enter で一致箇所を順に移動し、一致する行の位置をスクロールバーの横に表示し、一致のある行または列だけを残すこともできます。大きな結果はバックグラウンドで検索されるため、ウィンドウは応答し続けます。一致する行だけを表示している間は、コピーとエクスポートの対象もその行だけになります。

### 改善
- **スキーマ変換が移行先の実際の機能を使用：** 移行、スキーマの比較、他のエンジン向けのスクリプト、サブセット、ノートブックのテーブルで、移行先のエンジンが保持できる外部キー、インデックス、コメント、ベクトルインデックスを使って変換するようになりました。保持できないものは省かれ、スクリプトが失敗する代わりにレポートでその旨が示されます。
- **MCP クライアントと AI アシスタントによる Neo4j の読み取りをサーバーが強制：** Neo4j の読み取りアクセスモードで実行されるため、Neo4j 独自のベクトル関数を呼び出す読み取りやベクトルインデックスを検索する読み取りはすぐに実行され、書き込みはサーバー自体が拒否します。
- **Snowflake の整数ベクトル：** `VECTOR(INT, n)` は整数のベクトルとして読み取り、編集、比較、変換され、他のエンジンへ移す際も正確なまま保たれます。
- **Redis、Valkey、Dragonfly の検索インデックスが同一として比較される：** インデックスは、各サーバーがデフォルト値で報告する設定を除いて読み取られるため、同期後に同じインデックスがそれぞれで異なって表示されることはなくなりました。
- **DuckDB は HNSW インデックスを持つファイルを何もダウンロードせずに開く：** vss 拡張機能は、すでにインストールされている場合にのみ読み込まれ、DBine は書き込みで必要になったときにのみダウンロードします。
- **「データを比較」ですべての列を一度にキーにする：** **クエリ**モードで、列テーブルの**キー**ヘッダーにあるチェックボックスにより、対応付けられたすべての列をキーの一部としてマークするか、すべて解除できます。1 列ずつ操作する必要はありません。一部だけがマークされている間は、ダッシュが表示されます。
- **SQL ウェアハウスを待たない Databricks エクスプローラー：** Databricks への接続とカタログを開く操作は、停止中の SQL ウェアハウスの起動を待っていました。これには数分かかることがあり、大きなカタログのテーブルは `information_schema` を介して読み取られていました。エクスプローラーは、カタログ、スキーマ、テーブル、ビュー、関数を Unity Catalog から取得するようになりました。Unity Catalog はウェアハウスを必要とせず、数回の呼び出しで応答します。接続時にはこれまでどおりサインインとウェアハウスへのアクセスを確認し、停止していれば起動しますが、その完了は待ちません。クエリは従来どおり待機します。従来の `hive_metastore` と外部カタログは、引き続き SQL で読み取られます。
- **エクスプローラーはすぐに開き、他の場所での変更にも追従：** 接続を開いている間、エクスプローラーはそのデータベースとオブジェクトを前回の状態で表示し、サーバーからの応答で置き換えます。接続に失敗した場合は、そのエラーが表示されます。開いているものは、5 分後、DBine に戻ったとき、エディターで実行した `CREATE`、`ALTER`、`DROP`、名前変更の直後に、バックグラウンドで再読み込みされるため、DBine の外で作成または変更されたオブジェクトは**更新**しなくても表示されます。
- **エクスプローラーは大きなデータベースをフォルダーごとに表示：** データベースはスキーマを表示し、各フォルダー（テーブル、ビュー…）は開いたときに自分のオブジェクトを、データベース全体を一度に読み込む代わりに、**さらに読み込む**で 1,000 件ずつ表示します。補完は入力に合わせて名前とクエリで指定されたテーブルを検索し、エクスプローラーのフィルターは開いていないフォルダー内のオブジェクトを見つけ、「データを比較」とクエリビルダーのテーブル選択は入力しながら検索します。ほぼすべてのエンジンで、各フォルダー、検索、移動はサーバーに自分のオブジェクトだけを 1 ページずつ要求します。SQL Server のデータベースにビューが 50,000 個あっても、そのテーブルは約 10 ms で開きます。Power BI、Athena、Solr、Neptune、ksqlDB、Manticore、Databend、DuckDB 以外の Flight SQL サーバーは、一覧を一度だけ読み取り、DBine でページ分割します。
- **結果グリッドに各列のデータ型を表示：** グリッドのヘッダーに、各列のデータ型が名前の下に小さな文字で表示されます。設定 › 一般のスイッチで非表示にできます。
- **エクスプローラーから新しいノートブック：** 接続、データベース、スキーマを右クリックして、**新しいクエリ**の隣にある**新しいノートブック**を選択します。ノートブックは、セルがすでにその場所で実行されるように設定された状態で開きます。

### 修正
- **接続元の名前が移行スクリプトにコマンドを追加できる問題：** テーブルを MongoDB、Solr、Couchbase に移す際、DBine が調整したベクトルインデックスやフィールドについて書き込むメモに、接続元の名前がそのまま含まれていました。PostgreSQL など一部のエンジンでは、引用符で囲んだ名前の中に改行を含めることができます。改行を含む名前によってメモが途中で終了し、データベースの削除などのコマンドが追加され、それがあなたの権限で移行先で実行される可能性がありました。これらのメモ内の名前は、そうならないように書き込まれるようになりました。
- **数百万次元を主張する Oracle のベクトル：** Oracle が許容する次元数（65,535）を超える次元数を主張するテキストの疎ベクトルを、密な VECTOR 列にコピーまたは貼り付けすると、DBine がメモリ不足になることがありました。そのようなテキストは、ベクトルとして読み取られなくなりました。
- **db_owner のない SQL Server での「依存関係を表示…」：** `sys.sql_expression_dependencies` を読み取れないログインではエラーになっていました。今は、コードにそのテーブルまたはビューの名前が含まれるオブジェクトが定義の読み取りによって見つかり、確認できる権限がタブに表示されます。
- **エクスプローラーに表示されない OceanBase のシーケンス：** OceanBase 4.4 では、データベースのシーケンスが表示されませんでした。DBine が読み取っていたカタログビューは、データベースを ID だけで示します。現在は所有者で読み取られます。
- **幅の広いクエリで「データを比較」がメモリ不足になる問題：** 数百万行にわたる 60 列など、多数の列を持つ 2 つのクエリを比較すると、DuckDB の「Out of Memory Error: failed to pin block」で停止することがありました。数値の許容差も **NULL を空 (BLANK) と同一視**も使わない場合、各行は、テーブル比較と同様に、比較される値のハッシュとして DuckDB に渡され、比較はそのメモリに収まります。許容差または **NULL を空 (BLANK) と同一視**を使う場合、DuckDB は幅の広い結果に対して、より多くのメモリを使って 1 スレッドで動作します。
- **キーが重複する場合に「データを比較」がメモリ不足になる問題：** 少数の行でキーが重複する 2 つの大きなクエリ（たとえば Databricks テーブルの 1 か月分と 2 か月分）を比較すると、約 4,000,000 行で DuckDB の「Out of Memory Error: failed to allocate data of size 16.0 MiB」により停止することがありました。各キーの最初の行を残す方式では、差分を取得する間、DuckDB がすべての行を丸ごとメモリに保持していました。重複した行は、キーだけで見つかるようになりました。また DuckDB には、使用できるメモリ 64 MB につき最大 1 スレッドが割り当てられるため、コア数の多いマシンでも比較がメモリに収まります。
- **DataFrame SQL で SQL Server の数値がテキストになる問題：** 以前の SQL Server の結果に対するノートブックのセルは、NULL 許容の numeric、decimal、money、bit、date、time 列をテキストとして読み込んでいました。それらに対する `SUM` は失敗し、比較や並べ替えはテキストで行われていました。現在は、それぞれの型で読み込まれます。
- **「データを比較」がほぼすべての列をキーと推測する問題：** **クエリ**モードで、id のような列を持たない 1 つのテーブルに対するクエリでは、小数列以外のすべての列がキーになっていたため、比較で見つかるのは欠落した行だけで、変更された行は見つかりませんでした。現在は、そのテーブルの主キーまたは一意インデックスからキーが決まります。グループ化するクエリでは、これまでどおり説明的な列が使われます。明確な手がかりがない場合は何もマークされず、DBine がキーの指定を求めます。列テーブルの下の 1 行に、キーの出所が示されます。
- **クエリモードの「データを比較」が下で切れる問題：** 列が多いと、**クエリ**モードの列テーブルが数値の許容差、**同一の行を含める**、**比較**をウィンドウの下に押し出し、そこへ到達するためのスクロールもありませんでした。現在は、列テーブルがヘッダーを表示したまま単独でスクロールし、ウィンドウが低いときはタブの上部がスクロールします。
- **他の処理の背後でエクスプローラーが「読み込み中…」のままになる問題：** エクスプローラーでデータベースやテーブルを開くと、そのデータベースの構造を読み取っている他のすべての処理（エディターのオートコンプリート、スキーマの比較、移行、依存関係のスキャン）を待っていました。60 秒後に、接続がビジー状態であるというエラーで失敗することがありました。現在は、エクスプローラーは単独で読み取り、長い読み取りも同様なので、互いに待ち合うことはありません。
- **「データを比較」、エクスポート、コピーでの大きな Databricks テーブル：** 大きな Databricks テーブルの比較、コピー、エクスポートが「Databricks truncó el resultado… (25 MiB)… no se copia una tabla incompleta」で停止していました。このメッセージは誤った上限を示し、比較の場合でもコピーについて述べていました。Databricks が 1 回の読み取りで渡すのは最大 100 GiB で、これは内部形式で測定した値であり、テーブルがディスク上で占める容量の何倍にもなることがよくあります。現在は、大きなテーブルは部分ごとに読み取られ、Delta テーブルのすべての部分は同じバージョンで読み取られ、Databricks がそれでも切り詰めた部分は、より小さな部分で再度読み取られるため、不完全な読み取りが使われることはありません。Databricks が外部リンク経由でのテーブルの引き渡しを拒否した場合、クエリの送信後に拒否されたとしても、エラーに理由が示されるようになりました。
- **接続フォームの一部がスペイン語のままになる問題：** ドライバーが表示する一部のテキストが、インターフェイスの言語に関係なくスペイン語のままでした。Power BI のサインインアプリケーションとクエリ API のオプション、SQL Server と Azure SQL の Microsoft Entra ID のサインインモード、ODBC ドライバーのフィールドとそのヘルプ、Neo4j の暗号化のヘルプ、複数のフィールドの例、エクスプローラーの作成メニューの一部の項目などです。現在は、DBine が提供するすべての言語で表示されます。
- **Couchbase 8.0 の権限と関数：** 権限の一覧では、Couchbase Server 8.0 が報告する短い名前ではなく、GRANT が使う名前（`query_select`、`query_insert`、`query_update`、`query_delete`）でクエリロールが表示されます。関数、スコープ、コレクションを作成するスクリプトは、サーバーがそれを一覧表示するまで待機するため、エクスプローラーはすぐにそれを表示し、新しいスコープに作成したコレクションが「Scope not found」で失敗することもなくなりました。ステートメントが失敗した後は、スクリプトは待機を止めます。
- **10,000 を超えるベクトルを持つ Valkey の検索インデックス：** 数値フィールドを持たないインデックスの参照やコピーは、valkey-search の上限である 10,000 を超えるドキュメントが要求されても失敗しなくなりました。この上限のために不完全になるサブセットは、計画とレポートにその旨が示されます。
- **Redis の非圧縮 SVS-VAMANA インデックス：** 非圧縮インデックスのスクリプトは、Redis が拒否する圧縮設定を書き込まなくなりました。
- **libSQL の 1 ビットベクトル：** DBine の他の場所でビットベクトルが持つ形式である 0 と 1 として読み取られるようになりました。以前は 1 と -1 で、他のエンジンのビット列はこれをすべて 1 と解釈していました。1 ビットベクトルに手作業で作った L2 インデックスを持つテーブルのクローン、スクリプトのエクスポート、移行、比較は失敗しなくなりました。そのようなインデックスは順位付けが正しくないことが警告で示されます。
- **読み取りやコピーに失敗する openGauss のテーブル：** テーブルの読み取りやコピーが、COPY が終了マークなしで終わったというメッセージで失敗することがありました。openGauss はバイナリ COPY をそのマークなしで終了するため、DBine はそれを受け入れるようになりました。
- **検索インデックスのない MongoDB 7：** 検索インデックスの一覧を拒否する mongot のないサーバーは、検索インデックスを持たないものとして扱われ、一覧の取得に失敗した場合はその理由が示されます。
- **Cassandra と ScyllaDB の JSON 列：** 他のエンジンの JSON 値（PostgreSQL の jsonb のオブジェクトや配列など）は、テキスト列に JSON テキストとして書き込まれます。
- **DuckDB の HNSW インデックス：** DuckDB 1.5 が設定なしで一覧表示するインデックスの距離は拡張機能から読み取られるため、コサインインデックスがユークリッドとして読み取られることはなくなり、スキーマの比較では HNSW インデックスが設定によって区別されます。
- **スケジューラデザイナーでの OceanBase のイベント：** `'1:30' HOUR_MINUTE` のような複合間隔、または `WEEK` や `QUARTER` を持つイベントの保存は、構文エラーで失敗していました。OceanBase の `EVERY` が受け付けるのは SECOND、MINUTE、HOUR、DAY、MONTH、YEAR だけだからです。現在、フォームは OceanBase ではそれらだけを提示します（90 MINUTE は 1:30 HOUR_MINUTE と同じ働きをします）。「レプリカで無効」というステータスは OceanBase に存在しないため、そこでは提示されなくなりました。
- **`BEGIN … END` 本体を持つ OceanBase のイベント：** イベントを開き直した後、再度保存できませんでした。OceanBase はブロックを `BEGIN` と `END` なしで保存し、フォームは OceanBase が拒否するばらばらのステートメントを表示していたためです。現在は、フォームはそれを再びブロックとして表示します。OceanBase はセッションの設定にかかわらず、各イベント固有の SQL モードを保持するため、SQL モードのフィールドはそこでは読み取り専用で、フォームの注記にもその旨が示されます。以前は、フォームに入力したモードが知らされないまま保持されませんでした。
- **「ユーザーと権限」での OceanBase のロール：** `CREATE ROLE` で作成したロールが、ロックされたユーザーとして一覧表示されていました。OceanBase は MySQL と異なり、ロールのパスワード期限切れフラグを空にします。現在は、ロールはロールとして一覧表示されます。
- **macOS の IBM Db2 でデータが失われ、NULL が文字化けして表示される問題：** macOS 用の IBM ドライバーは、DBine が想定していなかったサイズで長さを報告します。NULL 値は NUL 文字の長い連続として読み取られ、NULL のセル、列の既定値、テーブルの説明とそこから作成されるスクリプトに含まれるコメントに影響していました。Db2 に複数行を一度に読み込むと（転送、コピー、テストデータ）、エラーなしで切り詰められた文字列や空の文字列が保存され、複数行の転送の読み取りは失敗していました。DBine は、接続時にそのようなドライバーを検出するようになりました。NULL は NULL になり、すべての行が完全に読み込まれます。そのドライバーを介した転送は 1 行ずつ読み取りと読み込みを行うため、遅くなります。
- **Db2 のスケジューラ：開始時刻を過ぎたタスクの編集：** **スケジュール › サーバー**では、開始時刻がすでに過去になっている Db2（LUW と z/OS）のタスクの編集が、開始時刻を過ぎているというメッセージですべて拒否され、変更のないタスクの保存も変更として扱われていました。Db2 は開始時刻をマイクロ秒単位で保持し、フォームは秒単位で表示します。現在は、秒単位で比較されます。

- **SQL Server の Windows サインイン（NTLM）：** 悪意のあるサーバーや傍受されたサーバーによって、DBine の NTLM 応答が自身の MIC フラグとサービス名を隠してしまう、または SQL Server ドライバーが数 GB のメモリを要求してしまう可能性がありました。DBine はこれらの長さを正しく書き込み、サーバーのオフセットを検証するようになりました。
- **AI アシスタントと他のデータベース：** Claude Code または Codex を使う場合、アシスタントはモデルが選んだ構造の読み取りのたびに確認し、接続が一覧に含めている場合にのみ、その接続の別のデータベースを読み取ります。サーバーが書き込んだテキスト（テーブルのコメントやオブジェクト名）が、ツールの応答やモデルへのあなたのメッセージになりすますことはできなくなりました。
- **バックアップからの SSH プロファイル：** バックアップから復元した SSH プロファイルを保存しても、確認なしでコマンドの出所が承認されることはなくなりました。また、プロファイルの ID がプロファイルのものではないバックアップは、復元されずに拒否されます。
- **KDB+ の予約名：** DBine は、kdb+ 自身の名前空間（`.z`、`.Q`…）、ルート、ファイルには決して書き込みません。悪意のあるサーバーの名前が単独（`.z`）、前後に空白付き、またはファイルハンドル（`:/path`）として届いた場合も同様で、スキーマ比較の同期スクリプトでも同じです。
- **エンジン間の同期スクリプト：** PostgreSQL から読み取った数値がテキストとしてスクリプトに入っていたため、型を保持する MongoDB などのエンジンでは `9` ではなく `"9"` が保存されたり、スクリプトが拒否されたりすることがありました。各値は、移行先の列が受け付ける形式で書き込まれるようになりました。
- **エンジン間でブール値を含むデータの比較：** PostgreSQL の `true` と `false` が他のエンジンのものと一致せず、ブール列を持つテーブルのすべての行が異なると表示され、同期スクリプトに移行先の列が受け付けない値が含まれることがありました。現在は本来の値として比較されます。
- **大きなテーブルでのデータの比較：** テーブルの行数が比較で読み取る行数（片側 200,000 行）を超える場合、両側が異なる行を読み取ることがあり、実際には存在する行が相手側にないと表示されたり、同期スクリプトがそれを削除または挿入したりすることがありました。両側がキー順で読み取られるようになり、部分的な比較では両側に存在する行のみが更新されます。
- **Databricks の大きな結果：** 結果が 25 MiB を超えるクエリは、先頭の行だけを表示する場合でも「Inline byte limit exceeded」で失敗していました。現在は要求した行を取得して部分的な結果として示し、エクスポートとグラフは結果全体を読み取ります。
- **Databricks の結果ダウンロード：** 結果の一部をダウンロードできなかった場合、一時的な資格情報を含むリンクがエラーに表示されていました。現在は表示されません。
- **SSH プロファイルの選択：** 接続の SSH トンネルタブで、プロファイルの一覧が空のボックスに縮んでいました。現在は行の幅いっぱいに表示され、接続が独自の設定を使用している場合はそのことが示されます。
- **スキーマを選択したときのスキーマを比較：** 全文検索カタログとストップリストが比較から消えなくなり、その差異が表示され、スクリプトはインデックスに必要なカタログを作成できます。
- **SQL Server の全文検索インデックスの同期：** 主キーの名前が異なるテーブルに移されたインデックスは、そのテーブルのキーを使用するようになり、その名前だけの差異は変更として表示されなくなりました。スキーマを比較で全文検索カタログまたはストップリストを削除すると、それを使用しているインデックスが一覧表示されます。
- **KDB+ への移行：** 再コピー（または中断したコピーの再開）のために kdb+ テーブルを空にしても、列、型、キーが保持され、列のない状態になりません。

### 修正
- **列の補完が、書いているクエリに追従します:** エディターには、カーソル位置のステートメントが読むテーブル、CTE、サブクエリの列だけが表示され、ファイル内の他のステートメントの列は表示されません。2 つのテーブルに共通する列はテーブルごとに 1 回ずつ表示され、エイリアスがラベルとして付き、修飾された形（`c.customer_id`）で挿入されます。CTE や派生テーブルの列は、クエリ内とそのエイリアスの後で表示されます。

### 修正
- **「検証しない」がサーバー証明書を固定するようになりました、セキュリティ:** サーバー証明書を検証しない接続（`sslmode=require`, `insecure`, `bolt+ssc`, `validate=false`…）は、サーバーが最初に提示した証明書を受け入れ、以降はその証明書だけを受け入れます。対象は PostgreSQL とその系列、HTTP エンジン（ClickHouse、Elasticsearch と OpenSearch、CouchDB、Trino、InfluxDB など）、Neo4j、Neptune、Redis、Cassandra です。証明書が変わると接続が停止し、2 つのフィンガープリントが表示されます。サーバーが証明書を更新した場合は **新しい証明書を信頼** を使用できます。SSL/TLS タブには固定されたフィンガープリントが表示され、**削除** できます。保存済みの接続は次回の接続時に固定されます。`verify-ca` とホスト名のみをスキップするオプションは、任意の証明書を受け入れる代わりに、チェーン全体を CA に対して検証するようになりました。SQL Server、MySQL、MariaDB、MongoDB、SAP HANA は、各クライアント独自の動作のままです。
- **再接続せずに新しいデータベースが表示:** クエリで `CREATE DATABASE` により作成（または削除、名前変更）したデータベースが、エクスプローラーとデータベース一覧にすぐ表示されます。また、データベース一覧（マイグレーション、比較、subset、バックアップ、権限、クエリのデータベース選択など）を開くと再読み込みされるため、別のツールで作成したデータベースも表示されます。
- **SQL Server Management Studio からのインポート:** 登録済みサーバーに加えて、SSMS の接続ダイアログが記憶しているサーバー（接続履歴）も、ログイン、データベース、暗号化の設定とともにインポートされます。SSMS 18 から 20、および SSMS 21 以降の新しいフォルダーに対応します。macOS と Linux では、ファイルダイアログで `RegSrvr.xml`、`UserSettings.xml`、`.regsrvr` ファイル（および DataGrip の `dataSources.xml`）を選べるようになりました。以前は JSON ファイルしか選べませんでした。
- **接続文字列のインポートで暗号化設定を保持:** 貼り付けまたはインポートした文字列が、各エンジン固有の TLS オプションを引き継ぎます。SQL Server の `Encrypt`（`Strict` を含む）と `HostNameInCertificate`、PostgreSQL の `sslmode` は記載どおり（`require` が検証付き接続になることはなくなりました）、MySQL の `ssl-mode` と Connector/J の `useSSL`、MariaDB の `sslMode`、そして `rediss://`、`bolt+s://`、`bolt+ssc://` スキームです。TLS 設定のない文字列は、そのクライアント自身が接続する場合と同じ設定でインポートされます。DBeaver、DataGrip やその他の JetBrains IDE、DbGate、Azure Data Studio からインポートした接続にも同様に適用されます。
- **macOS と Windows での証明書エラー:** システムが信頼しないサーバー証明書（"The certificate was not trusted"、"issued by an authority that is not trusted"、"The target principal name is incorrect"）がそのものとして認識され、汎用的な TLS エラーではなく、変更すべき TLS オプションがメッセージに示されます。
- **ClickHouse 22.8 以前:** 接続が `Unknown setting http_write_exception_in_output_format` で失敗しなくなりました。DBine はその設定を持たないサーバーには要求しません。
- **ノートブック、Python エクスポート:** サーバー証明書を検証する PostgreSQL 接続は、検証しない `require` ではなく、**接続文字列をコピー** と同じ `sslmode=verify-full` でエクスポートされます。
- **HashiCorp Vault、セキュリティ:** パスワードソースの Vault アドレスは `https://` である必要があります。他のシークレットマネージャーと同様、平文の `http://` はこのコンピューター上の Vault にのみ使えるため、Vault トークンがネットワーク上で平文で送られることはありません。

- **SQL ノートブック:** **ファイル › 新しいノートブック** でノートブックを開きます。任意の接続で実行できる SQL セルがそれぞれ結果とグラフを下に保持し、説明用のテキストセルも使えます。標準の Jupyter `.ipynb` として保存され、GitHub、VS Code、Jupyter で表示でき、Azure Data Studio や Jupyter の `%%sql` ノートブックでも開けます。ファイルには各結果のプレビュー(セルあたり 100 行と 1 MB、**設定 › ノートブック** で変更可)が総行数、時間、所要時間とともに保存され、接続の詳細やパスワードは保存されません。プロジェクト内では、有効にしない限りノートブックは結果なしで保存されます。アシスタントは、行を見ることなく、結果の説明、次のセルの提案、大きなクエリをグループ化したバージョンの提案ができます。HTML または Markdown にエクスポートできます。
- **結果全体を対象にしたグラフ:** グラフは、グリッドに読み込まれた行だけでなく、結果のすべての行を対象に計算されます。SQL エンジンではグループ化をサーバーで実行し、ノートブックの DataFrame SQL セルでは DuckDB が、その他のエンジンでは DBine が行います。
- **グラフの種類を追加:** ヒストグラム、ヒートマップ、箱ひげ図(ひげと外れ値付き)、棒と折れ線の組み合わせ、KPI(結果全体の合計)。
- **ノートブックのセルに複数のグラフ:** ノートブックのセルは、結果に対して複数のグラフを表示でき、マップが使うデータソースも記憶します。
- **ノートブックのエクスポートにグラフを含める:** HTML または Markdown にエクスポートしたノートブックに、グラフが画像として含まれます。
- **ノートブックで異なるデータベースの結果を結合:** 各セルの結果は、セルの名前(ヘッダーに表示され、編集できます)を持つ DataFrame になります。**DataFrame SQL** セルは、接続なしで、上にある DataFrame をテーブルとして DuckDB の SQL で照会・結合できるため、1 つのセルで PostgreSQL の結果と SQL Server や MongoDB の結果を結合できます。ファイルの書き込みやネットワークへのアクセスができないメモリ上の DuckDB データベースで実行され、ノートブックを閉じると破棄されます。各ソースの行は、このセッションでの実行結果、またはそのソース自身の接続で読み取り専用として再実行したクエリから取得されます(DataFrame あたり最大 1,000,000 行、**設定 › ノートブック** で変更可)。
- **スケジュール実行のレポートとしてのノートブック:** スケジュールタスクは、DBine を閉じたままノートブックを実行し(**ノートブックを実行**)、実行済みのコピーを保存して HTML または Markdown にエクスポートできます。次の **メールを送信** ステップで、それを添付するか、HTML エクスポートをメール本文として送信できます。無人実行中に確認を求めることはありません。読み取るのはそのノートブックで **常に許可** にしたファイルのみで、確認が必要な環境ではステップが明示的に許可した場合にのみ実行され、データを変更するセルはタスクの承認に含まれます。スケジュールされたエクスポートにはテーブルが含まれ、グラフはアプリからエクスポートするときに含まれます。
- **DataFrame SQL セルでローカルファイルを読み込み:** DataFrame SQL セルは、お使いのコンピューター上の CSV、Parquet、JSON、NDJSON、Excel ファイルを `read_csv`、`read_parquet`、`read_json`、`read_xlsx` で読み込めます(`data/*.csv` のようなパターンやファイルのリストにも対応)。地理ファイル(GeoJSON、付属ファイルを含む Shapefile、GeoPackage、KML、GPX、FlatGeobuf)は `st_read`、SQLite と DuckDB のデータベースファイルのテーブルは `sqlite_scan` と `read_duckdb` で読み込めます。いずれも DataFrame となり、どのエンジンのセルの結果とも結合できます。ジオメトリは `ST_Contains` などの空間関数でも引き続き使え、マップにも表示されます。ファイルは読み取るだけで、書き込むことはありません。ファイルを初めて読み込む前に、ノートブックが確認します。今回の実行のみ許可、このコンピューターでこのノートブックに常に許可(パターンは新しいファイルにも適用)、または拒否から選べます。資格情報、鍵、シェル履歴、システムファイルは読み込まれません。前回の実行からファイルの内容が変わっている場合は、結果にその旨が表示されます。設定 › ノートブックには各ノートブックが読み取れるファイルが一覧表示され、削除もできます。同じリーダーで、Web 上(`https://`)や Amazon S3、Google Cloud Storage、Azure Blob Storage(`s3://`、`gs://`、`az://`、`abfss://`、`s3://bucket/2026/*.parquet` のようなパターンも可)のファイルも読み込めます。承認は同じで、最初にサーバーが表示されます。DBine がファイルを自分でダウンロードして、読み込み後に削除される非公開の一時フォルダーに保存し、このコンピューターの AWS、Google Cloud、Azure のサインインを使います(AWS プロファイルは設定 › ノートブックで選択可)。ローカルやプライベートネットワークのアドレスには接続せず、他のサーバーへのリダイレクトにも従わず、URL に含まれた資格情報も受け付けません。他のプログラムで開いている GeoPackage には、`-wal` に残っている変更も含まれるようになりました。
- **ノートブックを Python ノートブックとしてエクスポート:** **エクスポート › Python ノートブック(.ipynb)** は、元のノートブックを再現する Jupyter ノートブックを書き出します。接続ごとに SQLAlchemy エンジン(または pymongo や redis など、エンジン固有の Python クライアント)が作られ、各クエリセルはセルの名前の pandas DataFrame に読み込まれ、DataFrame SQL セルはそれらの DataFrame 上で DuckDB により実行され、テキストセルは Markdown になります。パスワードとトークンはエクスポートされません。コードは環境変数から読み込み、最初のセルにその一覧とインストールするパッケージが記載されます。プレビューを含めるよう選ばない限り、結果は含まれません。
- **ノートブックから DataFrame をテーブルに書き込み:** **書き込みセル**(任意のセルの下に **テーブルに書き込み…** で追加)は、セルの結果全体を SQL Server、PostgreSQL、MySQL、MariaDB、Oracle、SQLite、DuckDB、MongoDB などのテーブルに書き込みます。挿入、キーによる更新、挿入または更新、テーブルの内容の置き換えが選べ、カラムのマッピングやプレビューがあり、必要なら新しいテーブルも作成できます。書き込みは毎回事前に確認し、書き込み先、方法、行数を表示します(本番の接続ではテーブル名の入力が必要)。トランザクションに対応するエンジンでは 1 つのトランザクションで実行され、読み取り専用の接続には書き込みません。スケジュールタスクでは、ステップがそのセル、テーブル、モードを許可している場合にのみ書き込みセルが実行されます。
- **ノートブックのパラメーター:** ノートブックでは、パラメーター(テキスト、数値、日付、日時、ブール値、固定リスト。既定値付き)を定義し、セルから `{{name}}` として使えます。実行時に不足している値を尋ね、各値はデータとしてデータベースに渡され(ドライバーによるバインド、またはエンジン自身の規則によるクォート)、各結果にはそれを生成した値が表示されます。
- **さらに 5 つの言語:** DBine とそのスマートフォンアプリが、スペイン語、英語、ポルトガル語、フランス語、イタリア語に加えて、ドイツ語、ロシア語、簡体字中国語、日本語、韓国語に対応しました。言語はシステムの言語に従い、使用中の言語だけが読み込まれます。

### 改善
- **macOS で署名済み:** macOS 版アプリは Apple Developer ID で署名され、Apple による公証を受けているため、「開発元を検証できません」という警告やターミナルのコマンドなしで開けます。署名済みバージョンを初めて開くと、DBine がキーチェーンの鍵を使用してよいか macOS が一度だけ尋ねます。**常に許可** を選んでください。
- **クラウドサインインはインスタンスの証明書のみを信頼:** AWS IAM、Google Cloud IAM、Microsoft Entra でサインインする接続と、インスタンスの CA ファイルを使う Cloud SQL および AlloyDB の接続は、トークンやパスワードを送信する前に、任意の公開証明書ではなく、その CA(または Amazon の RDS バンドル)のみを受け入れるようになりました。**サーバー証明書を信頼する** がオンの状態でパスワードを平文で要求するサーバーは、パスワードを受け取らず、接続に失敗します。
- **Windows で署名済み:** Windows のインストーラーとアプリはコード署名証明書で署名されているため、Windows には「不明な発行元」ではなく DBine の発行元が表示されます。
