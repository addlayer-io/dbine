# 変更履歴

## [1.2.2] - 2026-10-28

### 修正
- **セキュリティ：ZIP 処理の重大な脆弱性を修正しました。** 10 月 28 日、DBine が ZIP ベースのファイル（Excel のインポートとエクスポート、AI アシスタント内蔵モデルのダウンロード）の読み書きに使用するライブラリ `zip` で、重大な脆弱性が公開されました（[GHSA-m665-v7pm-7grj](https://github.com/advisories/GHSA-m665-v7pm-7grj)）。細工されたアーカイブは、読み込み方法によって異なる内容を表示する可能性がありました。このバージョンでは DBine のすべての部分を修正済みのライブラリに切り替えています。1.2.1 の数時間後にリリースされるのはこのためだけですので、アップデートをおすすめします。
- **Trino と Presto、セキュリティ：** 実在するどのスキーマよりも深くネストされた列の型（悪意のあるサーバーが送信する可能性があります）は、階層ごとに解析せず、届いたとおりに表示されるようになり、DBine がクラッシュすることはなくなりました。

## [1.2.1] - 2026-10-28

### 修正
- **列の補完が、書いているクエリに追従します:** エディターには、カーソル位置のステートメントが読むテーブル、CTE、サブクエリの列だけが表示され、ファイル内の他のステートメントの列は表示されません。2 つのテーブルに共通する列はテーブルごとに 1 回ずつ表示され、エイリアスがラベルとして付き、修飾された形（`c.customer_id`）で挿入されます。CTE や派生テーブルの列は、クエリ内とそのエイリアスの後で表示されます。
- **行と struct のフィールド名:** Trino と Presto の `ROW` 値、PostgreSQL の複合型、Arrow Flight SQL の struct で、各フィールドが名前付きの JSON として表示されます。入れ子の行、行の配列、値が行であるマップでも同様です（`[[42,[["demo-product",2]],null]]` ではなく `[{"customer_id":42,"items":[{"product_name":"demo-product","quantity":2}],"note":null}]`）。`null`、空文字列、空配列は区別されたままです。ClickHouse の名前付きタプルは宣言どおりのフィールド順を保ちます。
- **VIEW DEFINITION のない SQL Server ログインでの移行:** 移行元のログインがテーブルを読めても定義を読めない場合（Azure SQL でよくあります）、移行スクリプトが `CHECK ()` を書き出して「Incorrect syntax near ')'」で失敗し、列の既定値も通知なしに破棄されていました。今後は、これらの CHECK、既定値、計算式はスクリプトから除外され、プレビューと実行レポートの先頭に、理由と DBine が読み取れるようにする `GRANT VIEW DEFINITION` とともに 1 件ずつ一覧表示されます。生成されたスクリプトとスキーマ同期でも通知され、移行元が自身の CHECK を読めなかったことを理由に、同期が移行先の CHECK を削除することもなくなりました。空の CHECK や DEFAULT を書き出すエンジンはなくなりました。

### 改善
- **データベースをまたぐ補完:** 1 つのクエリで同じ接続内の別のデータベースを読めるエンジン（ClickHouse、MySQL と MariaDB、SQL Server、Snowflake、Databricks、Trino、BigQuery、Oracle など）で、エディターが他のデータベースの名前、`other_db.` の後のテーブル、テーブルまたはエイリアスの後の列を候補に表示します。データベースをまたぐ結合でも同様です。各データベースのテーブルは、その名前とドットを最初に入力したときに読み込まれます。
- **DuckDB エンジンを 2.0.0 に更新:** ローカルの DuckDB ファイルとノートブックの DataFrame SQL が DuckDB 2.0.0（従来は 1.5.5）で動作します。新しいデータベースファイルは DuckDB 2.0 のストレージ形式を使うため、古い DuckDB では開けません。既存のファイルは引き続き開け、作成したバージョンでも読み取れます。
- **SQL Server、PostgreSQL、MySQL の接続の暗号化:** 接続フォームに、各エンジンのツールで使われる名前で、そのエンジン固有の TLS オプションが表示されます。SQL Server と Azure SQL は `Encrypt`（Optional、Mandatory、Strict）、`TrustServerCertificate`、`ServerCertificate`、`HostNameInCertificate`、PostgreSQL とその系列は `sslmode` と `sslrootcert`、MySQL とその系列は `ssl-mode` と `ssl-ca`、MariaDB と OceanBase は `ssl`、`ssl-verify-server-cert`、`ssl-ca` です。新しい接続は暗号化され、サーバー証明書を検証します。各設定はオフにできます。保存済みの接続は従来どおり動作します。SSH トンネル経由では、証明書は実際のサーバー名に対して検証され、証明書エラーでは変更すべきオプションが示されます。MySQL の `PREFERRED` は、サーバーが TLS を提供しない場合にのみ、パスワードを送信する前に暗号化なしの接続へフォールバックします。
- **InfluxDB、IoTDB、ksqlDB、TDengine、Phoenix、Arrow Flight SQL、クラウドサービスの接続の暗号化:** 接続フォームに各エンジン固有の TLS オプションが表示されます。InfluxDB 1 は `ssl` と `unsafeSsl`、InfluxDB 2 は `skip-verify` 付きの URL スキーム、InfluxDB 3 は `tls-no-verify` と `tls-ca`、IoTDB と TimechoDB は `use_ssl` と `ca_certs`、ksqlDB は `useTls`、`verifyHost`、`trustStore`、TDengine は `useSSL`、Phoenix と Avatica は URL スキーム、`hostname_verification`、`truststore`、Flight SQL は `useEncryption` と `tlsRootCerts`、Cosmos DB エミュレーターは `DisableServerCertificateValidation` です。エンジンのツールに検証をスキップする名前や CA ファイルの名前がない場合は、curl の `insecure` と `cacert` を使います。新しい接続は暗号化され、サーバー証明書を検証します。各設定はオフにできます。保存済みの接続は従来どおり動作します。SSH トンネル経由では、証明書は実際のサーバー名に対して検証され、証明書エラーや TLS 非対応のサーバーはそのとおりに報告されます。BigQuery、Spanner、DynamoDB、Athena、Snowflake、Databricks、libSQL は常に検証付きの HTTPS を使います。ただし `http://` で入力したエミュレーターのエンドポイントは除きます。
- **キーボードとスクリーンリーダー:** 見えるフォーカスリングでキーボードの位置が分かります。リストの行、カード、並べ替え可能なヘッダー、折りたたみ可能なセクションは Tab で移動でき、Enter またはスペースで操作できます。コンテキストメニューは矢印キーで操作できます。アイコンのみのボタンにはスクリーンリーダーが読み上げる名前が付きました。クエリの結果（完了、またはエラーによる失敗）が通知されます。システムがモーションの軽減を求める場合はアニメーションが停止します。どちらのテーマでも補助テキストのコントラストが高くなりました。

### 修正
- **「検証しない」がサーバー証明書を固定するようになりました、セキュリティ:** サーバー証明書を検証しない接続（`sslmode=require`, `insecure`, `bolt+ssc`, `validate=false`…）は、サーバーが最初に提示した証明書を受け入れ、以降はその証明書だけを受け入れます。対象は PostgreSQL とその系列、HTTP エンジン（ClickHouse、Elasticsearch と OpenSearch、CouchDB、Trino、InfluxDB など）、Neo4j、Neptune、Redis、Cassandra です。証明書が変わると接続が停止し、2 つのフィンガープリントが表示されます。サーバーが証明書を更新した場合は **新しい証明書を信頼** を使用できます。SSL/TLS タブには固定されたフィンガープリントが表示され、**削除** できます。保存済みの接続は次回の接続時に固定されます。`verify-ca` とホスト名のみをスキップするオプションは、任意の証明書を受け入れる代わりに、チェーン全体を CA に対して検証するようになりました。SQL Server、MySQL、MariaDB、MongoDB、SAP HANA は、各クライアント独自の動作のままです。
- **再接続せずに新しいデータベースが表示:** クエリで `CREATE DATABASE` により作成（または削除、名前変更）したデータベースが、エクスプローラーとデータベース一覧にすぐ表示されます。また、データベース一覧（マイグレーション、比較、subset、バックアップ、権限、クエリのデータベース選択など）を開くと再読み込みされるため、別のツールで作成したデータベースも表示されます。
- **SQL Server Management Studio からのインポート:** 登録済みサーバーに加えて、SSMS の接続ダイアログが記憶しているサーバー（接続履歴）も、ログイン、データベース、暗号化の設定とともにインポートされます。SSMS 18 から 20、および SSMS 21 以降の新しいフォルダーに対応します。macOS と Linux では、ファイルダイアログで `RegSrvr.xml`、`UserSettings.xml`、`.regsrvr` ファイル（および DataGrip の `dataSources.xml`）を選べるようになりました。以前は JSON ファイルしか選べませんでした。
- **接続文字列のインポートで暗号化設定を保持:** 貼り付けまたはインポートした文字列が、各エンジン固有の TLS オプションを引き継ぎます。SQL Server の `Encrypt`（`Strict` を含む）と `HostNameInCertificate`、PostgreSQL の `sslmode` は記載どおり（`require` が検証付き接続になることはなくなりました）、MySQL の `ssl-mode` と Connector/J の `useSSL`、MariaDB の `sslMode`、そして `rediss://`、`bolt+s://`、`bolt+ssc://` スキームです。TLS 設定のない文字列は、そのクライアント自身が接続する場合と同じ設定でインポートされます。DBeaver、DataGrip やその他の JetBrains IDE、DbGate、Azure Data Studio からインポートした接続にも同様に適用されます。
- **macOS と Windows での証明書エラー:** システムが信頼しないサーバー証明書（"The certificate was not trusted"、"issued by an authority that is not trusted"、"The target principal name is incorrect"）がそのものとして認識され、汎用的な TLS エラーではなく、変更すべき TLS オプションがメッセージに示されます。
- **ClickHouse 22.8 以前:** 接続が `Unknown setting http_write_exception_in_output_format` で失敗しなくなりました。DBine はその設定を持たないサーバーには要求しません。
- **ノートブック、Python エクスポート:** サーバー証明書を検証する PostgreSQL 接続は、検証しない `require` ではなく、**接続文字列をコピー** と同じ `sslmode=verify-full` でエクスポートされます。
- **HashiCorp Vault、セキュリティ:** パスワードソースの Vault アドレスは `https://` である必要があります。他のシークレットマネージャーと同様、平文の `http://` はこのコンピューター上の Vault にのみ使えるため、Vault トークンがネットワーク上で平文で送られることはありません。

## [1.1.0] - 2026-10-21

### 新機能
- **クラウド同期の状態をひと目で確認:** ステータスバーに、緑の点付きで **同期済み**、変更のアップロード待ちの間はアンバー色で **アップロード待ち**、エラー時は赤で表示されます。ポイントすると最後の同期時刻が表示され、クリックすると同期設定が開きます。
- **接続文字列のコピー:** 接続を右クリックして(またはフォームのボタンから)**接続文字列をコピー…** を選ぶと、そのエンジンに対応する URI、ADO.NET、JDBC、SQLAlchemy、ODBC、libpq、Node.js、Go の形式で、あらゆるデータベースの接続文字列を TLS やサインインの設定込みで取得できます。パスワードは含まれず(`${DB_PASSWORD}` のプレースホルダーになります)、**パスワードを含める** をオンにした場合のみ、コピー時に取得され、1 分後にクリップボードに残っていれば消去されます。
- **メッセージを送信** ステップをスケジュールタスクに追加しました。実行結果を Microsoft Teams、Slack、Telegram、ntfy に投稿でき、タスクの変数(`{results}` は各ステップの内容を一覧にします)、メールのステップと同じ **条件**、**テスト** ボタンに対応します。Webhook URL とトークンはタスクではなくキーチェーンに保存され、メッセージは HTTPS でそのサービス自身のサーバーにのみ送信されます。

### 修正
- **SSH トンネル、セキュリティ:** SSH ライブラリを更新し、2 件のアドバイザリ(SSH エージェント経由のサービス拒否 CVE-2026-111061 と CVE-2026-111062)を修正しました。
- **RSA キー、セキュリティ:** RSA キーによる SSH へのサインイン、および Zoho Vault と Bitwarden の組織キーを開く処理を、AWS-LC で一定時間で実行するようにしました。これにより、RSA ライブラリのタイミングリーク(RUSTSEC-2023-0071、「Marvin」)は該当しなくなりました。RSA キーは SHA-256 または SHA-512 で署名します。SHA-1(`ssh-rsa`)のみを受け付けるサーバーでは、Ed25519 または ECDSA キー、もしくは SSH エージェントが必要です。
- **TLS、セキュリティ:** DBine と 33 のドライバーで TLS ライブラリとその証明書チェックを更新しました(RUSTSEC-2026-0346 から 0349、および 0381 から 0383)。これにより、信頼されなくなった認証局の証明書は拒否されます。更新されたドライバーは自動的にダウンロードされます。
- **組み込み AI エンジン:** エンジンの展開時、ファイルの読み取り・書き込み・実行の権限のみが保持されます。
- **スケジュールタスク、セキュリティ:** `{results}` と `{alerts}` は、メールとメッセージの本文にのみ展開されます。スクリプトの SQL、ファイル名やフォルダー名、アドレス、添付ファイルのパスには展開されなくなったため、細工されたデータをそのまま返すデータベースエラーが SQL やパスになることはありません。
- **スケジュールタスクのメッセージ:** メッセージやメール内の `{results}` と `{alerts}` が、常にスペイン語ではなく DBine の表示言語で出力されます。DBine を閉じたままタスクを実行した場合も同様です。
- **ノートブック、大きな DataFrame SQL の結果:** **詳細エクスポート… › すべて** が、表示中の行だけでなく結果全体を書き出します。セルの SQL は、前回の実行で読み込んだ DataFrame に対して DuckDB で再実行され、ファイルの再読み込みやソースへの再クエリは行われません。グラフは最初から結果全体で計算され、オフにすることもできます。結果が途中で切られている場合は、並べ替えと **すべてコピー** が読み込み済みの行だけが対象であることもグリッドに表示されます。

- **すべてのシークレットマネージャーのアカウント:** Bitwarden、Bitwarden Secrets Manager、HashiCorp Vault と OpenBao、Delinea、CyberArk Conjur と Central Credential Provider、1Password、AWS、Azure Key Vault、Google Secret Manager、KeePass は、**設定 › シークレットマネージャー** で一度だけ接続するようになりました。ガイド付きアシスタントが各値の場所を説明し、アカウントをその場で確認して、サインインしたユーザーを表示します。その後は、どの接続でもアカウントを選ぶだけで、資格情報はそのマネージャー自身のサーバーにのみ送信されます。
- **選べる Azure テナント:** Azure Key Vault のアカウントアシスタントが Microsoft Entra のテナントを一覧表示します(手入力も可能)。選んだテナントにサインインしていない場合は、コピーできる `az login --tenant` コマンドを表示します。
- **DataFrame SQL セルでのオートコンプリート:** 上のセルがテーブルとして候補に表示され(未実行のものも含む)、`name.` やエイリアスの後、および select リストでそのカラムが候補になります。FROM や JOIN の後には DuckDB のファイルリーダーも候補に出ます。リーダーを選ぶとカーソルが引用符の間に置かれ、**ファイルを選択…** でファイルダイアログが開きます。ノートブックの更新中に FROM の後のテーブル一覧が勝手に閉じることもなくなりました。
- **マップ表示:** ジオメトリ列(PostGIS、MySQL、SQL Server、SQLite/SpatiaLite、DuckDB、MongoDB、Elasticsearch など)または緯度・経度の列を含む結果を、内蔵のオフライン世界地図の上に、このマシン上で描画するマップで表示できます。詳細なオンライン地図タイルは **設定 › マップ** で有効にできます。その場合、プロバイダーには閲覧中の範囲が伝わりますが、データは伝わりません。
- **マップで Oracle に対応:** SDO_GEOMETRY 列が、テーブルのデータでも独自のクエリでも結果のマップに表示されるようになりました(サーバー側で SRID とともに WKT に変換)。これらのセルはグリッドでは読み取り専用です。
- **データファイルを直接開く:** SQLite、DuckDB、CSV、TSV、Parquet、JSON、Excel ファイルを、ダブルクリックや「DBine で開く」、ウィンドウへのドロップ、**ファイル › ファイルを開く…**(Cmd/Ctrl+O)で開けます。それぞれ一時的な接続として開き、**接続を保存** で保持できます。データファイルは先頭の 1,000 行がすぐに表示されます。
- **コマンドパレット:** Cmd/Ctrl+Shift+P であらゆる操作を検索して実行でき、現在のエンジンが対応するものだけが表示されます。**移動…**(Cmd/Ctrl+P)では、接続、データベース、テーブル、ビュー、ルーチン、保存したクエリ、開いているタブに移動できます。パレットのどの操作にも独自のショートカットを割り当てられます。
- **関連する行へ移動:** テーブルのデータやクエリの結果で、**参照先の行へ移動**(または Cmd/Ctrl+クリック)を選ぶと、その外部キーで絞り込んだ親テーブルが開きます。**これを参照している行** では、その値で絞り込んだ各子テーブルが開きます(複合キーにも対応)。外部キーがあるすべてのエンジンで使えます。
- **SQL ノートブック:** **ファイル › 新しいノートブック** でノートブックを開きます。任意の接続で実行できる SQL セルがそれぞれ結果とグラフを下に保持し、説明用のテキストセルも使えます。標準の Jupyter `.ipynb` として保存され、GitHub、VS Code、Jupyter で表示でき、Azure Data Studio や Jupyter の `%%sql` ノートブックでも開けます。ファイルには各結果のプレビュー(セルあたり 100 行と 1 MB、**設定 › ノートブック** で変更可)が総行数、時間、所要時間とともに保存され、接続の詳細やパスワードは保存されません。プロジェクト内では、有効にしない限りノートブックは結果なしで保存されます。アシスタントは、行を見ることなく、結果の説明、次のセルの提案、大きなクエリをグループ化したバージョンの提案ができます。HTML または Markdown にエクスポートできます。
- **結果全体を対象にしたグラフ:** グラフは、グリッドに読み込まれた行だけでなく、結果のすべての行を対象に計算されます。SQL エンジンではグループ化をサーバーで実行し、ノートブックの DataFrame SQL セルでは DuckDB が、その他のエンジンでは DBine が行います。
- **グラフの種類を追加:** ヒストグラム、ヒートマップ、箱ひげ図(ひげと外れ値付き)、棒と折れ線の組み合わせ、KPI(結果全体の合計)。
- **ノートブックのセルに複数のグラフ:** ノートブックのセルは、結果に対して複数のグラフを表示でき、マップが使うデータソースも記憶します。
- **ノートブックのエクスポートにグラフを含める:** HTML または Markdown にエクスポートしたノートブックに、グラフが画像として含まれます。
- **ノートブックで異なるデータベースの結果を結合:** 各セルの結果は、セルの名前(ヘッダーに表示され、編集できます)を持つ DataFrame になります。**DataFrame SQL** セルは、接続なしで、上にある DataFrame をテーブルとして DuckDB の SQL で照会・結合できるため、1 つのセルで PostgreSQL の結果と SQL Server や MongoDB の結果を結合できます。ファイルの書き込みやネットワークへのアクセスができないメモリ上の DuckDB データベースで実行され、ノートブックを閉じると破棄されます。各ソースの行は、このセッションでの実行結果、またはそのソース自身の接続で読み取り専用として再実行したクエリから取得されます(DataFrame あたり最大 1,000,000 行、**設定 › ノートブック** で変更可)。
- **スケジュール実行のレポートとしてのノートブック:** スケジュールタスクは、DBine を閉じたままノートブックを実行し(**ノートブックを実行**)、実行済みのコピーを保存して HTML または Markdown にエクスポートできます。次の **メールを送信** ステップで、それを添付するか、HTML エクスポートをメール本文として送信できます。無人実行中に確認を求めることはありません。読み取るのはそのノートブックで **常に許可** にしたファイルのみで、確認が必要な環境ではステップが明示的に許可した場合にのみ実行され、データを変更するセルはタスクの承認に含まれます。スケジュールされたエクスポートにはテーブルが含まれ、グラフはアプリからエクスポートするときに含まれます。
- **DataFrame SQL セルでローカルファイルを読み込み:** DataFrame SQL セルは、お使いのコンピューター上の CSV、Parquet、JSON、NDJSON、Excel ファイルを `read_csv`、`read_parquet`、`read_json`、`read_xlsx` で読み込めます(`data/*.csv` のようなパターンやファイルのリストにも対応)。地理ファイル(GeoJSON、付属ファイルを含む Shapefile、GeoPackage、KML、GPX、FlatGeobuf)は `st_read`、SQLite と DuckDB のデータベースファイルのテーブルは `sqlite_scan` と `read_duckdb` で読み込めます。いずれも DataFrame となり、どのエンジンのセルの結果とも結合できます。ジオメトリは `ST_Contains` などの空間関数でも引き続き使え、マップにも表示されます。ファイルは読み取るだけで、書き込むことはありません。ファイルを初めて読み込む前に、ノートブックが確認します。今回の実行のみ許可、このコンピューターでこのノートブックに常に許可(パターンは新しいファイルにも適用)、または拒否から選べます。資格情報、鍵、シェル履歴、システムファイルは読み込まれません。前回の実行からファイルの内容が変わっている場合は、結果にその旨が表示されます。設定 › ノートブックには各ノートブックが読み取れるファイルが一覧表示され、削除もできます。同じリーダーで、Web 上(`https://`)や Amazon S3、Google Cloud Storage、Azure Blob Storage(`s3://`、`gs://`、`az://`、`abfss://`、`s3://bucket/2026/*.parquet` のようなパターンも可)のファイルも読み込めます。承認は同じで、最初にサーバーが表示されます。DBine がファイルを自分でダウンロードして、読み込み後に削除される非公開の一時フォルダーに保存し、このコンピューターの AWS、Google Cloud、Azure のサインインを使います(AWS プロファイルは設定 › ノートブックで選択可)。ローカルやプライベートネットワークのアドレスには接続せず、他のサーバーへのリダイレクトにも従わず、URL に含まれた資格情報も受け付けません。他のプログラムで開いている GeoPackage には、`-wal` に残っている変更も含まれるようになりました。
- **ノートブックを Python ノートブックとしてエクスポート:** **エクスポート › Python ノートブック(.ipynb)** は、元のノートブックを再現する Jupyter ノートブックを書き出します。接続ごとに SQLAlchemy エンジン(または pymongo や redis など、エンジン固有の Python クライアント)が作られ、各クエリセルはセルの名前の pandas DataFrame に読み込まれ、DataFrame SQL セルはそれらの DataFrame 上で DuckDB により実行され、テキストセルは Markdown になります。パスワードとトークンはエクスポートされません。コードは環境変数から読み込み、最初のセルにその一覧とインストールするパッケージが記載されます。プレビューを含めるよう選ばない限り、結果は含まれません。
- **ノートブックから DataFrame をテーブルに書き込み:** **書き込みセル**(任意のセルの下に **テーブルに書き込み…** で追加)は、セルの結果全体を SQL Server、PostgreSQL、MySQL、MariaDB、Oracle、SQLite、DuckDB、MongoDB などのテーブルに書き込みます。挿入、キーによる更新、挿入または更新、テーブルの内容の置き換えが選べ、カラムのマッピングやプレビューがあり、必要なら新しいテーブルも作成できます。書き込みは毎回事前に確認し、書き込み先、方法、行数を表示します(本番の接続ではテーブル名の入力が必要)。トランザクションに対応するエンジンでは 1 つのトランザクションで実行され、読み取り専用の接続には書き込みません。スケジュールタスクでは、ステップがそのセル、テーブル、モードを許可している場合にのみ書き込みセルが実行されます。
- **ノートブックのパラメーター:** ノートブックでは、パラメーター(テキスト、数値、日付、日時、ブール値、固定リスト。既定値付き)を定義し、セルから `{{name}}` として使えます。実行時に不足している値を尋ね、各値はデータとしてデータベースに渡され(ドライバーによるバインド、またはエンジン自身の規則によるクォート)、各結果にはそれを生成した値が表示されます。
- **さらに 5 つの言語:** DBine とそのスマートフォンアプリが、スペイン語、英語、ポルトガル語、フランス語、イタリア語に加えて、ドイツ語、ロシア語、簡体字中国語、日本語、韓国語に対応しました。言語はシステムの言語に従い、使用中の言語だけが読み込まれます。

### 改善
- **macOS で署名済み:** macOS 版アプリは Apple Developer ID で署名され、Apple による公証を受けているため、「開発元を検証できません」という警告やターミナルのコマンドなしで開けます。署名済みバージョンを初めて開くと、DBine がキーチェーンの鍵を使用してよいか macOS が一度だけ尋ねます。**常に許可** を選んでください。
- **クラウドサインインはインスタンスの証明書のみを信頼:** AWS IAM、Google Cloud IAM、Microsoft Entra でサインインする接続と、インスタンスの CA ファイルを使う Cloud SQL および AlloyDB の接続は、トークンやパスワードを送信する前に、任意の公開証明書ではなく、その CA(または Amazon の RDS バンドル)のみを受け入れるようになりました。**サーバー証明書を信頼する** がオンの状態でパスワードを平文で要求するサーバーは、パスワードを受け取らず、接続に失敗します。
- **Windows で署名済み:** Windows のインストーラーとアプリはコード署名証明書で署名されているため、Windows には「不明な発行元」ではなく DBine の発行元が表示されます。

- **サーバーモニター:** 数値、テーブル、注記が、一部のラベルがスペイン語のまま表示されることなく、すべてのエンジンで翻訳されるようになりました。
