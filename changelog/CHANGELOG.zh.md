# 更新日志

## [1.7.0] - 2026-11-21

### 新增
- **向量（embedding）：** DBine 可在存储向量的引擎中读取、编辑、建立索引、比较、迁移和搜索向量，例如带 pgvector 的 PostgreSQL、MySQL、Oracle、SQL Server、Snowflake、Elasticsearch、OpenSearch、Redis 及其同类、MongoDB、Cassandra、DuckDB、libSQL 和 Neo4j。向量单元格显示其前几个数值和一个标明维度的徽章，单元格查看器会给出元素类型、范数、最小值和最大值。编辑在到达服务器之前，会先按列的维度和元素范围进行校验。每个引擎保留各自的类型、索引算法和距离度量。
- **设计器和资源管理器中的向量索引：** 表设计器可创建和编辑向量索引（HNSW、IVFFlat、DiskANN，以及各引擎提供的其他类型），并设置其距离和参数；资源管理器在“索引”选项卡中列出它们。Redis、Valkey 和 Dragonfly 在键数据库内的单独文件夹中列出其搜索索引，菜单中提供其字段和模板，并可删除这些索引。
- **比较、传输和转换中的向量：** 架构比较与同步、数据比较、传输、克隆、迁移、子集、测试数据、脱敏和架构转换都会在引擎之间携带向量及其索引。当目标无法精确保存某些内容时，转换报告会说明改变或舍弃了什么以及原因，例如二进制向量上的 Hamming 索引在 libSQL 中保留为余弦索引，或对 Cosmos DB 过宽的 flat 索引改为量化索引。
- **笔记本、导出、数据库文档和助手中的向量：** DataFrame SQL、导出、数据库文档、AI 助手和 MCP 工具都能识别向量列和索引。编辑器会补全各引擎的向量函数和运算符。
- **资源管理器的筛选可找到未打开的内容，也包括代码内部：** 输入时，筛选会在已打开的数据库中查找文本，先查资源管理器上次记住的内容（立即返回），再按名称查询服务器，并在各自的文件夹（表、视图…）中显示每个匹配项，无需手动展开。启用 **</>** 后，还会在定义内部查找：视图、存储过程、函数、触发器，以及 Power BI 的度量值和表（其 Power Query 和 DAX）。这些匹配项带有 **代码** 标签，并标出文本所在的行。Power BI 中的**在数据库中搜索…**现在也会搜索表的 Power Query 和计算列。BigQuery 对每次元数据查询计费，因此在其上，筛选仅在按下 **Enter** 时才询问服务器。
- **沿袭，以及对象使用了什么：** **查看依赖项…**现在还会列出对象自身使用的内容：视图读取的表和视图、存储过程调用的例程、其外键指向的表，以及数据库之外的源。**查看沿袭…**以图的形式绘制两个方向，左侧是它所使用的内容，右侧是使用它的对象，每张卡片可向任一方向再展开一层。实线来自引擎的目录，虚线来自对代码的解析，单击会显示提到另一个对象的代码行。每个引擎在有依赖目录的情况下读取各自的目录：SQL Server、Oracle、PostgreSQL 及其同系列、MySQL 8、Db2、SAP HANA、Firebird、ClickHouse、Snowflake、MongoDB 视图和 Cassandra。Databricks 使用 Unity Catalog 的沿袭，Power BI 使用 `INFO.CALCDEPENDENCY` 和每个表的 Power Query 源。链接服务器、数据库链接、外部表、其他数据库以及 Power BI 的数据源显示为数据库之外的源。服务器的作业也包含在内：SQL Server Agent 作业、pg_cron 和 pgAgent 作业、`DBMS_SCHEDULER` 作业、MySQL 事件，以及其步骤会运行某个对象的其他计划作业，都显示在它的右侧，因此沿袭可以从一张表，经过使用它的视图和存储过程，一直到运行它们的作业。作业自身的沿袭（从**已计划 › 在服务器上**打开）显示其步骤使用的内容。
- **整个数据库的沿袭：** 右键单击数据库、架构、文件夹（表、视图…）或 Power BI 模型 › **查看沿袭…**，会在一张图中绘制它的所有对象和所有依赖，包括数据库之外的源和服务器的作业。对象超过约 200 个时，会以概览形式打开，每个架构一张卡片，双击可展开其中一个；可按类型和文本筛选，可仅显示已确认的线，也可仅显示有依赖的对象。关系（外键和 Power BI 模型的关系）与沿袭并行，因此开关可让它们与沿袭一同显示，或只保留沿袭；在整个数据库视图中，它们默认隐藏。SQL Server、PostgreSQL 及共用其目录的引擎、Oracle、Db2、SAP HANA、MySQL 和 MariaDB、ClickHouse、Snowflake、Databricks、MongoDB 视图以及 Power BI 的整个模型从各自的目录读取，并在打开选项卡时加载；其他引擎会显示扫描的作用和一个**分析**按钮，因为扫描要读取所有定义。
- **在结果中搜索：** 在结果网格中按 ⌘F（Ctrl+F），或点击结果栏上的放大镜，会在所有已加载的行和列中搜索，而不仅限于屏幕上可见的部分，并高亮匹配项。它会列出有匹配的列及每列的匹配数（单击可将搜索限定在某一列），按 Enter 在匹配项之间跳转，在滚动条旁标出匹配行的位置，并可仅保留有匹配的行或列。大型结果在后台搜索，因此窗口保持响应。仅显示匹配行时，复制和导出只提供这些行。

### 改进
- **架构转换使用目标实际具备的功能：** 迁移、架构比较、面向其他引擎的脚本、子集和笔记本表现在会按目标引擎能够保存的外键、索引、注释和向量索引进行转换。无法保存的内容会被舍弃，并在报告中说明，而不是让脚本因此失败。
- **MCP 客户端和 AI 助手对 Neo4j 的读取由服务器强制执行：** 它们在 Neo4j 的读访问模式下运行，因此调用 Neo4j 自带向量函数或搜索向量索引的读取会立即运行，而写入会被服务器本身拒绝。
- **Snowflake 整数向量：** `VECTOR(INT, n)` 会作为整数向量读取、编辑、比较和转换，这样在迁移到其他引擎时能保持精确。
- **Redis、Valkey 和 Dragonfly 的搜索索引比较结果为相同：** 读取索引时会忽略各服务器按默认值报告的设置，因此同一个索引在同步后不再于两端显示为不同。
- **DuckDB 打开带 HNSW 索引的文件时无需下载任何内容：** 仅当 vss 扩展已安装时才加载它，只有写入需要时 DBine 才会下载它。
- **在“比较数据”中一次将所有列标记为键：** 在**查询**模式下，列表格**键**表头中的复选框可将所有已配对的列标记为键的一部分，或全部取消，而不必逐个操作。仅部分列被标记时，它显示为短横线。
- **Databricks 资源管理器无需等待 SQL warehouse：** 连接 Databricks 并打开目录时，以前要等待已停止的 SQL warehouse 启动（可能需要几分钟），大型目录的表也是通过 `information_schema` 读取的。现在资源管理器从 Unity Catalog 获取目录、架构、表、视图和函数，它不需要 warehouse，几次调用即可响应。连接时仍会检查您的登录以及对 warehouse 的访问权限，并在其已停止时启动它，但不再等待：查询会像以前一样等待它。旧版 `hive_metastore` 和外部目录仍通过 SQL 读取。
- **资源管理器立即打开，并跟进在别处所做的更改：** 连接打开时，资源管理器会按上次的样子显示其数据库和对象，随后由服务器的响应替换。如果连接失败，则显示其错误。已打开的内容会在五分钟后、回到 DBine 时，以及在编辑器中运行 `CREATE`、`ALTER`、`DROP` 或重命名之后立即在后台重新读取，因此在 DBine 之外创建或更改的对象无需**刷新**即可显示。
- **资源管理器按文件夹逐个显示大型数据库：** 数据库显示其架构，每个文件夹（表、视图…）在打开时显示各自的对象，每次 1,000 个，点击**加载更多**继续，而不是一次显示整个数据库。补全会在输入名称时查找名称以及查询中提到的表，资源管理器的筛选可在未打开的文件夹中找到对象，“比较数据”和查询生成器的表选择器也会边输入边搜索。在几乎所有引擎上，每个文件夹、搜索和跳转都只向服务器请求各自的对象，一次一页：在有 50,000 个视图的 SQL Server 数据库中，其表约 10 ms 即可打开。Power BI、Athena、Solr、Neptune、ksqlDB、Manticore、Databend 以及 DuckDB 以外的 Flight SQL 服务器只读取一次列表，并在 DBine 中分页。
- **结果网格中每列的数据类型：** 网格表头在每列名称下方以小字显示该列的类型。可在“设置 › 常规”中用开关将其隐藏。
- **从资源管理器新建笔记本：** 右键单击连接、数据库或架构，选择**新建笔记本**，它位于**新建查询**旁边。笔记本打开时，其单元格已设置为在该处运行。

### 修复
- **来源中的名称可能向迁移脚本添加命令：** 当表迁移到 MongoDB、Solr 或 Couchbase 时，DBine 写入的关于其不得不调整的向量索引或字段的说明，会原样带上来源的名称。某些引擎（如 PostgreSQL）允许在带引号的名称内换行。含有换行的名称可能终止说明并添加一条命令（例如删除数据库），随后以您的权限在目标上运行。现在这些说明中的名称在写入时已无法做到这一点。
- **声称有数百万维的 Oracle 向量：** 将文本声称维度超过 Oracle 上限（65,535）的稀疏向量复制或粘贴到稠密的 VECTOR 列中，可能导致 DBine 内存耗尽。这样的文本不再被读取为向量。
- **没有 db_owner 的 SQL Server 上的“查看依赖项…”：** 无权读取 `sys.sql_expression_dependencies` 的登录名会收到错误。现在会得到代码中提到该表或视图的对象（通过读取其定义找到），选项卡还会说明哪项权限可以确认它们。
- **资源管理器中缺少 OceanBase 序列：** 在 OceanBase 4.4 上，数据库的序列不显示。DBine 读取的目录视图仅通过 id 指明数据库。现在改为按所有者读取。
- **宽查询的“比较数据”内存不足：** 比较两个列很多的查询（例如数百万行、60 列）时，可能因 DuckDB 的 “Out of Memory Error: failed to pin block” 而停止。在没有数值容差且未启用 **NULL 等同于空白 (BLANK)** 时，每一行现在以其被比较的值的哈希形式交给 DuckDB，与表比较的做法相同，比较可在其内存内完成。启用容差或 **NULL 等同于空白 (BLANK)** 时，DuckDB 对宽结果使用单线程和更多内存。
- **键重复时“比较数据”内存不足：** 比较两个键在少数几行中重复的大型查询（例如 Databricks 表一个月的数据对比两个月的数据），在约 4,000,000 行时可能因 DuckDB 的 “Out of Memory Error: failed to allocate data of size 16.0 MiB” 而停止。保留每个键的第一行会使 DuckDB 在带回差异时把所有行完整保存在内存中；现在仅凭键即可找到重复的行。此外，DuckDB 每 64 MB 可用内存最多分配一个线程，因此比较在多核机器上也能放入内存。
- **DataFrame SQL 中 SQL Server 数字变成文本：** 基于先前 SQL Server 结果的笔记本单元格，会把其可为空的 numeric、decimal、money、bit、date 和 time 列加载为文本。对它们的 `SUM` 会失败，比较和排序按文本进行。现在它们按其类型加载。
- **“比较数据”为几乎所有列猜测键：** 在**查询**模式下，针对单张表且没有类似 id 的列的查询，会把除小数列外的所有列作为键，因此比较只能发现缺失的行，永远发现不了被修改的行。现在键来自该表的主键或唯一索引。带分组的查询仍使用其描述性列。没有明确线索时不标记任何列，DBine 会请您指定键。列表格下方的一行文字说明键的来源。
- **查询模式下的“比较数据”底部被截断：** 列很多时，**查询**模式的列表格会把数值容差、**包含相同的行**和**比较**推到窗口之外，且无法滚动到它们。现在列表格自行滚动，表头保持可见，窗口较矮时选项卡的上半部分也可滚动。
- **资源管理器因其他工作而停在“正在加载…”：** 在资源管理器中打开数据库或表，会等待其他所有正在读取该数据库结构的操作：编辑器的补全、架构比较、迁移或依赖项扫描。它可能在 60 秒后失败，提示连接繁忙。现在资源管理器独立读取，耗时较长的读取也是如此，因此互不等待。
- **“比较数据”、导出和复制中的大型 Databricks 表：** 比较、复制或导出大型 Databricks 表时会停止，并提示 “Databricks truncó el resultado… (25 MiB)… no se copia una tabla incompleta”，该提示指出了错误的上限，并且即使在比较中也说成复制。Databricks 每次读取最多交付 100 GiB（按其内部格式计），这往往是表在磁盘上所占大小的数倍。现在大型表会分段读取，Delta 表的各段取自同一版本，Databricks 仍会截断的分段则以更小的分段重新读取，因此绝不会使用不完整的读取。当 Databricks 拒绝通过外部链接交付表时，错误现在会给出原因，即使拒绝发生在查询发送之后。
- **连接表单部分为西班牙语：** 驱动程序显示的某些文本无论界面语言如何都保持西班牙语。其中包括 Power BI 的登录应用和查询 API 选项、SQL Server 和 Azure SQL 的 Microsoft Entra ID 登录模式、ODBC 驱动程序字段及其帮助、Neo4j 的加密帮助、多个字段中的示例，以及资源管理器创建菜单的某些项。现在它们以 DBine 提供的所有语言显示。
- **Couchbase 8.0 权限和函数：** 权限列表现在以 GRANT 使用的名称（`query_select`、`query_insert`、`query_update`、`query_delete`）显示查询角色，而不是 Couchbase Server 8.0 报告的短名称。创建函数、scope 或 collection 的脚本会等待服务器将其列出，因此资源管理器随后立即显示它，在新 scope 中创建的 collection 也不再因 “Scope not found” 而失败。语句失败后，脚本不再等待。
- **超过 10,000 个向量的 Valkey 搜索索引：** 浏览或复制没有数值字段的索引时，请求超过 10,000 个文档（valkey-search 的上限）不再失败。因该上限而不完整的子集会在计划和报告中说明。
- **Redis 未压缩的 SVS-VAMANA 索引：** 未压缩索引的脚本不再写入 Redis 拒绝的压缩设置。
- **libSQL 1 位向量：** 它们按 0 和 1 读取，这是 DBine 其他位置位向量的形式，而不是 1 和 -1（另一个引擎的位列会把后者当作全为 1）。对带有手工创建的 1 位向量 L2 索引的表进行克隆、脚本导出、迁移或比较不再失败；警告会说明这样的索引排序有误。
- **openGauss 表无法读取或复制：** 读取或复制表时可能失败，提示 COPY 在没有结束标记的情况下结束。openGauss 的二进制 COPY 不带该标记，DBine 现在接受这种情况。
- **没有搜索索引的 MongoDB 7：** 没有 mongot 的服务器会拒绝列出搜索索引，现在被视为没有搜索索引，列出失败时会说明原因。
- **Cassandra 和 ScyllaDB 的 JSON 列：** 来自其他引擎的 JSON 值（例如 PostgreSQL jsonb 的对象或数组）会以其 JSON 文本写入文本列。
- **DuckDB HNSW 索引：** DuckDB 1.5 列出时不带设置的索引，其距离现在从扩展中读取，因此余弦索引不再被读成欧氏索引，架构比较也会按设置区分 HNSW 索引。
- **调度器设计器中的 OceanBase 事件：** 保存带复合间隔（如 `'1:30' HOUR_MINUTE`）或带 `WEEK` 或 `QUARTER` 的事件会因语法错误而失败，因为 OceanBase 的 `EVERY` 只接受 SECOND、MINUTE、HOUR、DAY、MONTH 和 YEAR。现在表单在 OceanBase 上只提供这些（90 MINUTE 的效果与 1:30 HOUR_MINUTE 相同）。OceanBase 中不存在“在副本上禁用”状态，现在不再提供。
- **带 `BEGIN … END` 主体的 OceanBase 事件：** 事件重新打开后无法再次保存，因为 OceanBase 存储的代码块不含 `BEGIN` 和 `END`，而表单显示的是它拒绝的零散语句。现在表单会再次将其显示为代码块。OceanBase 为每个事件保留其自身的 SQL 模式，与会话的模式无关，因此那里的 SQL 模式字段为只读，表单中的说明也这样提示；此前在表单中输入的模式会被悄悄丢弃。
- **“用户和权限”中的 OceanBase 角色：** 用 `CREATE ROLE` 创建的角色被列为已锁定的用户。与 MySQL 不同，OceanBase 将角色的密码过期标志留空；现在角色会被列为角色。
- **macOS 上的 IBM Db2 丢失数据并将 NULL 显示为乱码：** IBM 的 macOS 驱动程序以 DBine 未预期的大小报告长度。NULL 值被读成很长的 NUL 字符串，影响了 NULL 单元格、列默认值，以及表说明及据此生成的脚本中的注释。一次向 Db2 加载多行（传输、复制、测试数据）会在没有任何错误的情况下存入被截断或为空的字符串，多行传输的读取也会失败。现在 DBine 在连接时检测此类驱动程序：NULL 就是 NULL，每一行都完整加载。通过该驱动程序的传输逐行读取和加载，因此较慢。
- **Db2 调度器：编辑开始时间已过的任务：** **已计划 › 在服务器上**会拒绝对开始时间已在过去的 Db2（LUW 和 z/OS）任务的任何编辑，并提示开始时间已过，保存未更改的任务也被算作更改。Db2 将开始时间保存到微秒，而表单显示到秒；现在按秒比较。

## [1.6.3] - 2026-11-18

### 改进
- **匿名使用数据按使用天数计数：** 当 DBine 从一天开到下一天时，新一天的第一次点击或按键会像打开应用一样计数，安装后的首次启动也会被标记出来。除此之外不会发送任何内容：依然没有你、电脑或安装的任何标识符，**设置 › 常规**仍可像以前一样将其关闭。具体发送的内容列在遥测文档中。
- **导出“比较数据”的结果：** 列表旁的**导出…**可将屏幕上的列表保存为 CSV、Excel、JSON、SQL、XML 或其他结果导出格式。可以是不同的行、仅存在于一侧的行，或相同的行。通过列表筛选的每一行都会按其顺序导出，而不只是屏幕上的行。不同的行会将每一列的左右两侧的值并排放置，最后一列注明哪些列不同。

### 修复
- **方向键让结果网格的视图落在后面：** 用方向键将所选单元格移到结果网格的右边缘或左边缘之外时，视图停在原处，选区会跑出屏幕；编辑单元格时按 Tab 和 Enter 也会如此。现在网格会跟随单元格滚动，横向和纵向都是如此。
- **导出“在多个数据库上运行”的结果时只写入屏幕上的行：** 网格保留编辑器设置的每个数据库的最大行数，**导出**只保存这些行，而不是完整结果。现在导出会在每个数据库上依次以只读方式重新运行查询，并将所有行写入文件，合并后的网格中 `base` 列排在最前面。某个数据库失败时会停止导出并指明是哪一个，也不会留下写到一半的文件。
- **SQL Server 资源管理器等待其他会话的更改：** 当另一个会话（例如 ETL 或部署脚本）开着一个创建或修改对象的事务时，打开某个数据库的表、存储过程或其他对象可能会停滞 60 秒并失败，提示服务器没有响应。现在资源管理器会立即读取它们，连同它们的列、定义以及自动补全使用的架构。只有该事务正在修改的那个对象本身的源代码仍需等待。
- **计划任务的邮件，安全：** 发送邮件的库已更新，修复了其 SMTP 代码中的六项安全公告。服务器，或位于 DBine 与服务器之间的人，可能在 STARTTLS 前后伪造服务器的回复；以单个换行符结尾的行可能把 SMTP 命令混入通信；带有引号部分的地址可能被发送给其他收件人；格式错误的回复可能中断发送或占满内存。这涉及 **发送电子邮件** 步骤和 **设置 › 邮件**。

## [1.6.0] - 2026-11-14

### 新增
- **服务器作业：** **已计划**现在分为两个部分：**在 DBine 中**，即由 DBine 运行的任务；**在服务器上**，即每台数据库服务器自行运行的作业。其中包括 SQL Server Agent 作业、Oracle DBMS_SCHEDULER、pg_cron、pgAgent 和 TimescaleDB 作业、Snowflake 任务、Databricks 作业、MySQL 事件、BigQuery 计划查询、Couchbase 备份、CouchDB 复制等。每个作业都会显示其计划、步骤以及带消息的运行历史，并在引擎允许时提供**立即运行**、**停止**、**启用** / **禁用**和**查看脚本**。引擎自带的作业在你选择显示之前保持隐藏，只读连接只显示作业。连接菜单中的**服务器作业**会打开该连接的作业组。
- **关闭 DBine 后保留结果：** 每个查询编辑器的结果标签页会保存到你电脑上的加密文件中，因此在关闭 DBine 或崩溃之后，每个编辑器都会按原样重新显示它们（包括已固定的），无需运行任何内容。密钥始终不会离开你的电脑和用户；在**设置 › 常规**中可设置它们可占用的空间、清除它们，或关闭此功能。
- **会自我说明的监视器指标：** 监视器仪表板上的每个指标都会说明它衡量什么、如何解读，以及其值来自哪个视图、查询或 API 字段。**指标**用于选择显示哪些指标，并按引擎记住；点击某个指标会将其放大，在可缩放的时间线上显示最近一小时。
- **计划程序设计器：** **已计划 › 在服务器上**现在可以完整管理每台服务器的计划程序。它拥有的每种对象，例如 SQL Server Agent 的作业、计划、操作员、警报、代理和类别，Oracle DBMS_SCHEDULER 的作业、程序、计划、链和窗口，pg_cron、pgAgent 和 TimescaleDB 的作业，以及事件、任务、转换和可刷新视图，都在专为其引擎打造的设计器中创建、编辑和删除，并且在运行任何内容之前会先显示脚本。编辑只更改发生变化的部分，引擎允许时就地修改；当更改需要重新创建对象或会丢失其历史记录时，DBine 会说明并在继续前询问。在引擎支持的情况下，作业可以从其某一步开始并清除其历史记录，每种对象都有自己的操作（立即运行、打开窗口、刷新视图等），还可以读取计划程序自身的日志。引擎自有的对象受到保护，只读连接会显示表单和脚本，但不会更改任何内容。
- **命名结果：** 语句正上方的行注释（`-- 客户汇总`）会为其结果命名。每条命名语句都有自己的结果标签页，无论运行的是整个脚本、选中的部分还是仅该语句；再次运行会就地刷新该标签页，保留结果数量的上限也不会将其关闭。结果标签页也可以双击重命名。
- **在编辑器中只运行一条语句：** 当编辑器中有两条或更多语句时，每条语句上方会出现一个小的 **▶ 运行**（引擎支持计划时还有**计划**），若语句有名称则一并显示，且只运行该语句。可在**设置 › 常规**中关闭。在 Elasticsearch、OpenSearch、Solr、CouchDB、MongoDB、Redis、Valkey、Dragonfly、etcd、KDB+、Cassandra、Neo4j、Cosmos DB、InfluxDB 1 和 DynamoDB 上，编辑器会按引擎运行的方式识别每条语句，例如带请求体的控制台请求或每行一条命令，因此 **▶ 运行**以及运行光标处的语句在这些引擎上同样可用。
- **需要填写值的计划程序操作：** **已计划 › 在服务器上**中的某些操作会在其脚本之前打开一个表单。BigQuery 传输可针对过去的日期运行，Databricks 作业可用其他参数运行，TDengine 流可重新计算某个时间范围，Oracle 正在运行的链可更改或停止某一步，Couchbase 可合并某个日期范围内的备份，Snowflake 任务可用另一配置运行一次，Elasticsearch 转换可从某个时间开始，watch 只确认所选的操作，OpenSearch 监视器则确认所选的警报。与所有操作一样，脚本会在运行前显示并确认。
- **所有引擎的函数补全：** 编辑器会建议连接所用引擎及版本的函数，附带其参数、返回类型，以及服务器提供时的说明；选择其中一个会写入 `name()`，光标位于括号内。大多数引擎从服务器列出函数，因此扩展和你自己的函数也包括在内；其余引擎使用其文档为该版本列出的函数。没有 SQL 函数的语言会得到起同样作用的内容：Redis、Valkey、Dragonfly 和 etcd 的命令，MongoDB 和 CouchDB 的运算符，Solr 的函数查询，Cypher 和 Flux 的函数，以及 Elasticsearch、OpenSearch 和 Solr 控制台中的 SQL 行。DataFrame SQL 笔记本单元格使用 DuckDB 的函数。
- **Power BI 和 Microsoft Fabric 语义模型：** 新增一种引擎。使用 Microsoft 账户（或服务主体）登录，浏览工作区和模型及其表、列、度量值、关系、层次结构和角色，并用 DAX 查询，支持高亮和补全，适用于 Pro、Premium 每用户和 Fabric 容量。结果可像其他任何引擎一样导出和绘制图表。模型的刷新属于服务器作业：历史记录、立即刷新和计划。模型的权限、名称、说明和删除都可在 DBine 中管理，并在运行任何内容之前显示脚本。
- **DAX 的代码质量和优化查询：** 在 Power BI 上，编辑器会标出常见的 DAX 陷阱，例如 CALCULATE 中对整张表使用 FILTER、IFERROR 和 ISERROR、用 `/` 代替 DIVIDE、带计算列的 SUMMARIZE，以及没有 ORDER BY 的 TOPN。**优化查询**会为其中大多数提供重写方案，在结果可能改变时标记为先比较。
- **比较两个查询的结果：** **比较数据**现在可以比较两个查询而不是两张表，适用于任意引擎及跨引擎，例如将 Power BI 度量值与源数据库上的 SUM 比较。比较的是完整结果，并可为舍入设置数值容差；可从比较视图打开，也可通过查询编辑器和结果中的**与…比较**打开。

### 改进
- **测试连接：** 当**测试连接**失败时，错误会显示在按钮旁边，**出了什么问题…**会对其进行说明（防火墙、超时、DNS、TLS 或凭据），与已保存的连接一样。
- **监视器进程：** 所选会话会在列表旁的面板中打开，列表保持原位，面板显示其完整语句和**分析**（将其带到优化器），此外还可取消该语句或结束会话。方向键可在会话之间切换。

- **比较数据中的架构：** 每一侧在各自的列表中选择架构，再选择该架构中的表，这对架构很多的服务器很有帮助。

- **Oracle 和 SQL Server 的监视器 CPU：** 数据库的 CPU 现在是占服务器所有 CPU 的比例。多个核心繁忙时，它曾显示超过 100 %，例如五个核心时显示 500 %。
- **更多引擎的监视器 CPU 超过 100 %：** 在 MySQL、MongoDB、ClickHouse、SAP HANA、Redis、Dragonfly、Elasticsearch、OpenSearch、Solr、InfluxDB、Neo4j、Couchbase、IoTDB、etcd、CockroachDB、openGauss、Trino、Db2、SAP ASE、SQL Anywhere 和 Informix 上，CPU 是占单个核心的比例，可能显示几百个百分点。现在它是占服务器可使用的所有 CPU 的比例。

- **大表的数据比较：** **比较数据…**现在比较整张表，在每个引擎上都能处理数百万行，而不再在每侧 200,000 行处停止。大表会经过一份加密的本地副本，比较结束时会将其删除。比较会显示已读取的行数并可取消，其计数也始终一致：超出另一侧最后读取行之后的行，不再显示为仅存在于一侧。
- **粘贴连接字符串：** 最后一个值是单独的引号或花括号（`Password="`）的 SQL Server 或 ODBC 连接字符串会导致导入失败；现在会将其读取为该字符。
- **带转义名称的脚本：** 在 ClickHouse 和 BigQuery 上，名称中带有反斜杠转义的反引号时，在查询中打开脚本不再将其拆分为多条语句。
- **openGauss 作业：** 启用作业或运行其脚本不再失败，也不会让服务器崩溃。
- **Dremio reflection 脚本：** 它们把 `DISTRIBUTE BY` 写在了 `PARTITION BY` 之后，而 Dremio 会拒绝；现在的顺序是 Dremio 接受的顺序。
- **pgAgent 作业：** 无权访问 pgagent 架构的用户在列出作业时不再收到 “permission denied for schema pgagent”。
- **Snowflake 任务图：** 任务图的 finalizer 曾被列为单独的作业；现在它属于其根任务的作业。
- **在比较数据中选择键：** 一次比较之后，选择其他表会让键列表仍保留上一次比较的列；现在会提供新表的列，并且任一侧发生变化时结果会立即丢弃。
- **实际计划快捷键：** **运行并包含实际计划**的提示在某些语言中显示 ⌘⇧↵，实际应为 ⌘⇧L。
- **安全，依赖项：** DBine 及其驱动的 HTTP 客户端所用的 QUIC 库已更新，修复了三个公告（RUSTSEC-2026-0523、RUSTSEC-2026-0524、RUSTSEC-2026-0538）。服务器可能打开超出允许数量的流，用过长的 Retry 令牌使客户端崩溃或耗尽其内存，或用被截断的数据报使其空转。更新后的驱动会自动下载。

- **两个库的安全修复：** DuckDB 驱动的 Arrow 库，以及 DBine 及其 DuckDB、SAP HANA 和 MySQL 驱动使用的一个系统库，已更新到修复内存安全问题的版本（RUSTSEC-2026-0442、RUSTSEC-2026-0486）。
- **SQL Server 的 Windows 登录（NTLM）：** 恶意或被截获的服务器可能使 DBine 的 NTLM 响应隐藏自身的 MIC 标志和服务名称，或使 SQL Server 驱动申请数 GB 内存。现在 DBine 会正确写入这些长度，并检查服务器给出的偏移量。
- **AI 助手与其他数据库：** 使用 Claude Code 或 Codex 时，助手会在模型选择的每次结构读取之前询问；只有连接列出了某个数据库，助手才会读取该连接的其他数据库。服务器写入的文本（表注释、对象名称）也不能再冒充工具的回答或您发给模型的消息。
- **备份中的 SSH 配置：** 保存从备份恢复的 SSH 配置时，不再未经询问就确认其命令来源；如果备份中的配置带有不是配置标识符的 ID，将被拒绝而不是恢复。
- **KDB+ 保留名称：** DBine 绝不会写入 kdb+ 自身的命名空间（`.z`、`.Q`…）、根或文件，即使恶意服务器给出的名称是单独的（`.z`）、前后带空白，或是文件句柄（`:/path`），例如在架构比较的同步脚本中。
- **引擎之间的同步脚本：** 从 PostgreSQL 读取的数字会以文本形式进入脚本，因此 MongoDB 等保留类型的引擎可能存入 `"9"` 而不是 `9`，或拒绝该脚本。现在每个值都按目标列接受的方式写入。
- **跨引擎比较含布尔值的数据：** PostgreSQL 的 `true` 和 `false` 与其他引擎的不匹配，因此含布尔列的表的每一行都显示为不同，同步脚本也可能带上目标列不接受的值。现在它们按其实际含义进行比较。
- **大表上的比较数据：** 当表的行数超过一次比较读取的数量（每侧 200,000 行）时，两侧可能读取不同的行，因此某行可能被显示为另一侧缺失而实际并非如此，同步脚本也可能删除或插入该行。现在两侧都按键顺序读取，部分比较只会更新两侧都存在的行。
- **Databricks 中的大型结果：** 结果超过 25 MiB 的查询会以“Inline byte limit exceeded”失败，即使只显示了前几行。现在它会返回你请求的行并标记为部分结果，导出和图表则读取完整结果。
- **Databricks 结果下载：** 当结果的某一部分无法下载时，错误信息会显示其链接，而链接中带有临时凭据。现在不再显示。
- **SSH 配置文件选择器：** 在连接的 SSH 隧道选项卡中，配置文件列表曾缩成一个空框。现在它占满整行宽度，并在连接使用自身设置时给出提示。
- **选中架构时的比较架构：** 全文目录和停用词表不再从比较中消失，因此它们的差异会显示，脚本也可以创建索引所需的目录。
- **同步 SQL Server 全文索引：** 将索引带到主键名称不同的表时，现在使用该表的键，仅名称不同也不再显示为更改。在比较架构中删除全文目录或停用词表时，现在会列出使用它的索引。
- **迁移到 KDB+：** 为重新复制（或恢复中断的复制）而清空 kdb+ 表时，会保留其列、类型和键，而不是让它没有列。

## [1.2.1] - 2026-10-28

### 修复
- **列补全跟随你正在编写的查询:** 编辑器只提供光标所在语句读取的表、CTE 和子查询的列，而不是文件中其他语句的列。两张表共有的列会按表各提供一次，以别名作为标签，并以限定形式插入（`c.customer_id`）；CTE 或派生表的列会在查询内部以及其别名之后提供。
- **行和 struct 中的字段名:** Trino 和 Presto 的 `ROW` 值、PostgreSQL 的复合类型以及 Arrow Flight SQL 的 struct 以 JSON 形式按名称显示每个字段，嵌套行、行数组以及值为行的映射中也是如此（`[{"customer_id":42,"items":[{"product_name":"demo-product","quantity":2}],"note":null}]`，而不是 `[[42,[["demo-product",2]],null]]`）。`null`、空字符串和空数组仍可区分。ClickHouse 的命名元组保持声明的字段顺序。

- **从 SQL Server Management Studio 导入：** 除已注册的服务器外，DBine 现在还会导入 SSMS 连接对话框记住的服务器（其连接历史），包括登录名、数据库和加密设置，支持 SSMS 18 到 20 以及 SSMS 21 及更高版本的新文件夹。在 macOS 和 Linux 上，文件对话框现在接受 `RegSrvr.xml`、`UserSettings.xml` 和 `.regsrvr` 文件（以及 DataGrip 的 `dataSources.xml`）；此前只能选择 JSON 文件。

- **macOS 和 Windows 上的证书错误：** 系统不信任的服务器证书（“The certificate was not trusted”“issued by an authority that is not trusted”“The target principal name is incorrect”）现在能被识别，消息会说明应更改哪个 TLS 选项，而不是显示笼统的 TLS 错误。
- **ClickHouse 22.8 及更早版本：** 连接不再因 `Unknown setting http_write_exception_in_output_format` 而失败；DBine 不再向没有该设置的服务器请求它。
- **笔记本，Python 导出：** 校验服务器证书的 PostgreSQL 连接现在导出为 `sslmode=verify-full`，与 **复制连接字符串** 一致，而不是不做校验的 `require`。
- **HashiCorp Vault，安全：** 密码来源的 Vault 地址必须是 `https://`；仅本机上的 Vault 才接受明文 `http://`，与其他密钥管理器一致，因此 Vault 令牌绝不会在网络上以明文传输。
