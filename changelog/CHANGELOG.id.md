### Peningkatan
- **Pelengkapan lintas basis data:** pada engine yang kuerinya dapat membaca basis data lain dalam koneksi yang sama (ClickHouse, MySQL dan MariaDB, SQL Server, Snowflake, Databricks, Trino, BigQuery, Oracle, dan lainnya), editor menawarkan nama basis data lain, tabelnya setelah `other_db.`, dan kolomnya setelah tabel atau alias, termasuk dalam join antarbasis data. Tabel setiap basis data dibaca saat nama basis data itu diketik pertama kali dengan tanda titik.
- **Engine DuckDB diperbarui ke 2.0.0:** file DuckDB lokal dan DataFrame SQL di notebook kini berjalan di DuckDB 2.0.0 (sebelumnya 1.5.5). File basis data baru memakai format penyimpanan DuckDB 2.0 yang tidak dapat dibuka oleh DuckDB versi lama; file yang sudah ada tetap dapat dibuka dan tetap dapat dibaca oleh versi yang membuatnya.
- **Enkripsi koneksi untuk SQL Server, PostgreSQL, dan MySQL:** formulir koneksi menampilkan opsi TLS milik masing-masing engine, dengan nama yang dipakai alatnya: `Encrypt` (Optional, Mandatory, Strict), `TrustServerCertificate`, `ServerCertificate`, dan `HostNameInCertificate` untuk SQL Server dan Azure SQL; `sslmode` dan `sslrootcert` untuk PostgreSQL dan keluarganya; `ssl-mode` dan `ssl-ca` untuk MySQL dan keluarganya; `ssl`, `ssl-verify-server-cert`, dan `ssl-ca` untuk MariaDB dan OceanBase. Koneksi baru dienkripsi dan memeriksa sertifikat server, dan setiap pengaturan dapat dimatikan. Koneksi tersimpan tetap berfungsi persis seperti sebelumnya. Melalui terowongan SSH, sertifikat diperiksa terhadap nama server yang sebenarnya, dan kegagalan sertifikat menyebutkan opsi mana yang perlu diubah. `PREFERRED` pada MySQL beralih ke koneksi tanpa enkripsi hanya jika server tidak menawarkan TLS, sebelum kata sandi apa pun dikirim.
- **Enkripsi koneksi untuk InfluxDB, IoTDB, ksqlDB, TDengine, Phoenix, Arrow Flight SQL, dan layanan cloud:** formulir koneksi menampilkan opsi TLS milik masing-masing engine: `ssl` dan `unsafeSsl` untuk InfluxDB 1, skema URL dengan `skip-verify` (InfluxDB 2) atau `tls-no-verify` dan `tls-ca` (InfluxDB 3), `use_ssl` dan `ca_certs` untuk IoTDB dan TimechoDB, `useTls`, `verifyHost`, dan `trustStore` untuk ksqlDB, `useSSL` untuk TDengine, skema URL, `hostname_verification`, dan `truststore` untuk Phoenix dan Avatica, `useEncryption` dan `tlsRootCerts` untuk Flight SQL, serta `DisableServerCertificateValidation` untuk emulator Cosmos DB; jika alat suatu engine tidak punya nama untuk melewati pemeriksaan atau untuk file CA, dipakai `insecure` dan `cacert` dari curl. Koneksi baru dienkripsi dan memeriksa sertifikat server, dan setiap pengaturan dapat dimatikan. Koneksi tersimpan tetap berfungsi persis seperti sebelumnya. Melalui terowongan SSH, sertifikat diperiksa terhadap nama server yang sebenarnya, dan kegagalan sertifikat atau server tanpa TLS dilaporkan apa adanya. BigQuery, Spanner, DynamoDB, Athena, Snowflake, Databricks, dan libSQL selalu memakai HTTPS yang diverifikasi, kecuali endpoint emulator yang diketik sebagai `http://`.
- **Papan ketik dan pembaca layar:** cincin fokus yang terlihat menunjukkan posisi papan ketik; baris daftar, kartu, header yang dapat diurutkan, dan bagian yang dapat dilipat dapat dijangkau dengan Tab dan digunakan dengan Enter atau Spasi; menu konteks berfungsi dengan tombol panah; tombol yang hanya berisi ikon memiliki nama yang dibaca pembaca layar; hasil kueri (selesai, atau gagal beserta galatnya) diumumkan; animasi berhenti saat sistem meminta pengurangan gerakan; dan teks sekunder memiliki kontras lebih tinggi di kedua tema.

### Perbaikan
- **Basis data baru muncul tanpa menyambung ulang:** basis data yang dibuat dengan `CREATE DATABASE` dalam kueri (atau dihapus, atau diganti namanya) langsung muncul di penjelajah dan daftar basis data, dan membuka daftar basis data (migrasi, perbandingan, subset, pencadangan, izin, pemilih basis data pada kueri…) membacanya kembali, sehingga basis data yang dibuat dari alat lain juga muncul.
- **Impor dari SQL Server Management Studio:** selain server terdaftar, DBine kini mengimpor server yang diingat oleh dialog Connect SSMS (riwayat koneksinya), beserta login, basis data, dan pengaturan enkripsinya, dari SSMS 18 hingga 20 dan folder baru SSMS 21 ke atas. Di macOS dan Linux, dialog file kini menerima file `RegSrvr.xml`, `UserSettings.xml`, dan `.regsrvr` (serta `dataSources.xml` milik DataGrip); sebelumnya hanya file JSON yang dapat dipilih.
- **Impor string koneksi mempertahankan pengaturan enkripsinya:** string yang ditempel atau diimpor kini membawa opsi TLS-nya sebagai opsi milik engine: `Encrypt` SQL Server (termasuk `Strict`) dan `HostNameInCertificate`, `sslmode` PostgreSQL sebagaimana tertulis (`require` tidak lagi menjadi koneksi yang diverifikasi), `ssl-mode` MySQL dan `useSSL` Connector/J, `sslMode` MariaDB, serta skema `rediss://`, `bolt+s://`, dan `bolt+ssc://`. String tanpa pengaturan TLS diimpor sebagaimana kliennya sendiri akan menyambung. Hal yang sama berlaku untuk koneksi yang diimpor dari DBeaver, DataGrip dan IDE JetBrains lainnya, DbGate, dan Azure Data Studio.
- **Galat sertifikat di macOS dan Windows:** sertifikat server yang tidak dipercaya sistem ("The certificate was not trusted", "issued by an authority that is not trusted", "The target principal name is incorrect") kini dikenali sebagaimana mestinya, dan pesan menyebutkan opsi TLS mana yang perlu diubah, bukan galat TLS yang umum.
- **ClickHouse 22.8 dan yang lebih lama:** menyambung tidak lagi gagal dengan `Unknown setting http_write_exception_in_output_format`; DBine berhenti meminta pengaturan itu pada server yang tidak memilikinya.
- **Notebook, ekspor Python:** koneksi PostgreSQL yang memeriksa sertifikat server diekspor dengan `sslmode=verify-full`, seperti yang dilakukan **Salin string koneksi**, bukan `require` yang tidak memeriksanya.
- **HashiCorp Vault, keamanan:** alamat Vault sumber kata sandi harus `https://`; `http://` biasa hanya diterima untuk Vault di komputer ini, seperti pada pengelola rahasia lainnya, sehingga token Vault tidak pernah dikirim sebagai teks biasa melalui jaringan.
