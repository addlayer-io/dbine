# Зміни


## [1.2.1] - 2026-10-28

### Виправлення
- **Автодоповнення стовпців стежить за запитом, який ви пишете:** редактор пропонує лише стовпці таблиць, CTE і підзапитів, які читає інструкція під курсором, а не стовпці інших інструкцій файлу. Стовпець, спільний для двох таких таблиць, пропонується по одному разу для кожної таблиці, з підписом у вигляді псевдоніма, і вставляється з кваліфікатором (`c.customer_id`); стовпці CTE і похідної таблиці пропонуються всередині запиту та після її псевдоніма.
- **Імена полів у рядках і структурах:** значення `ROW` у Trino і Presto, складені типи PostgreSQL і структури Arrow Flight SQL показують кожне поле під його іменем, у вигляді JSON, зокрема у вкладених рядках, масивах рядків і словниках, значення яких є рядками (`[{"customer_id":42,"items":[{"product_name":"demo-product","quantity":2}],"note":null}]` замість `[[42,[["demo-product",2]],null]]`). `null`, порожній рядок і порожній масив, як і раніше, відрізняються. Іменовані кортежі ClickHouse зберігають оголошений порядок полів.
- **Міграції з логіном SQL Server без VIEW DEFINITION:** якщо вихідний логін міг читати таблиці, але не їхні визначення (часто в Azure SQL), скрипт міграції записував `CHECK ()`, що завершувалося помилкою "Incorrect syntax near ')'", і мовчки відкидав значення стовпців за замовчуванням. Тепер такі CHECK, значення за замовчуванням і обчислювані вирази виключаються зі скрипта, а попередній перегляд і звіт про виконання перелічують кожен із них угорі, з причиною та `GRANT VIEW DEFINITION`, який дає DBine змогу їх прочитати. Згенеровані скрипти та синхронізація схем теж повідомляють про це, а синхронізація більше не видаляє CHECK у цільовій базі через те, що джерело не змогло прочитати власний. Жоден рушій більше не записує порожній CHECK чи DEFAULT.

## [1.2.0] - 2026-10-27

### Нове
- **Українська та польська:** DBine і застосунок для телефона доступні мовами Українська та Polski, зокрема повідомлення сервера й ШІ-асистент. Оберіть мову в **Налаштування › Загальні › Мова**, або DBine використає мову системи.
- **Індонезійська:** DBine і застосунок для телефона доступні мовою Bahasa Indonesia, зокрема повідомлення сервера й ШІ-асистент. Оберіть мову в **Налаштування › Загальні › Мова**, або DBine використає мову системи.

### Покращення
- **Автодоповнення між базами даних:** у рушіях, де один запит може читати іншу базу того самого підключення (ClickHouse, MySQL і MariaDB, SQL Server, Snowflake, Databricks, Trino, BigQuery, Oracle та інші), редактор пропонує назви інших баз, їхні таблиці після `other_db.` та їхні стовпці після таблиці або псевдоніма, зокрема в об'єднаннях між базами. Таблиці кожної бази читаються під час першого введення її назви з крапкою.
- **Рушій DuckDB оновлено до 2.0.0:** локальні файли DuckDB і DataFrame SQL у ноутбуках тепер працюють на DuckDB 2.0.0 (раніше 1.5.5). Нові файли баз використовують формат зберігання DuckDB 2.0, який старіші версії DuckDB відкрити не можуть; наявні файли й далі відкриваються та залишаються доступними для читання версією, що їх створила.
- **Шифрування підключення для SQL Server, PostgreSQL і MySQL:** форма підключення показує параметри TLS кожного рушія з назвами, які використовують його інструменти: `Encrypt` (Optional, Mandatory, Strict), `TrustServerCertificate`, `ServerCertificate` і `HostNameInCertificate` для SQL Server і Azure SQL; `sslmode` і `sslrootcert` для PostgreSQL та його родини; `ssl-mode` і `ssl-ca` для MySQL та його родини; `ssl`, `ssl-verify-server-cert` і `ssl-ca` для MariaDB і OceanBase. Нові підключення шифруються й перевіряють сертифікат сервера, а кожен параметр можна вимкнути. Збережені підключення працюють точно так, як раніше. Через SSH-тунель сертифікат перевіряється за назвою справжнього сервера, а за помилки сертифіката повідомляється, який параметр змінити. `PREFERRED` у MySQL переходить на незашифроване підключення, лише якщо сервер не пропонує TLS, до надсилання будь-якого пароля.
- **Шифрування підключення для InfluxDB, IoTDB, ksqlDB, TDengine, Phoenix, Arrow Flight SQL і хмарних сервісів:** форма підключення показує параметри TLS кожного рушія: `ssl` і `unsafeSsl` для InfluxDB 1, схема URL із `skip-verify` (InfluxDB 2) або `tls-no-verify` і `tls-ca` (InfluxDB 3), `use_ssl` і `ca_certs` для IoTDB і TimechoDB, `useTls`, `verifyHost` і `trustStore` для ksqlDB, `useSSL` для TDengine, схема URL, `hostname_verification` і `truststore` для Phoenix і Avatica, `useEncryption` і `tlsRootCerts` для Flight SQL та `DisableServerCertificateValidation` для емулятора Cosmos DB; якщо в інструментів рушія немає назви для пропуску перевірки або для файла CA, використовуються `insecure` і `cacert` з curl. Нові підключення шифруються й перевіряють сертифікат сервера, а кожен параметр можна вимкнути. Збережені підключення працюють точно так, як раніше. Через SSH-тунель сертифікат перевіряється за назвою справжнього сервера, а помилка сертифіката або сервер без TLS повідомляються як такі. BigQuery, Spanner, DynamoDB, Athena, Snowflake, Databricks і libSQL завжди використовують перевірений HTTPS, окрім адреси емулятора, введеної як `http://`.
- **Клавіатура й програми зчитування з екрана:** видима рамка фокуса показує, де перебуває клавіатура; рядки списків, картки, заголовки з сортуванням і розділи, що згортаються, доступні клавішею Tab і працюють з Enter або пробілом; контекстні меню працюють зі стрілками; кнопки лише зі значком мають назви, які читає програма зчитування з екрана; результат запиту (завершено або завершено помилкою) озвучується; анімації вимикаються, коли система просить зменшити рух; а другорядний текст має вищу контрастність в обох темах.

### Виправлення
- **«Не перевіряти» тепер закріплює сертифікат сервера, безпека:** з'єднання, яке не перевіряє сертифікат сервера (`sslmode=require`, `insecure`, `bolt+ssc`, `validate=false`…), приймає сертифікат, який сервер пред'являє вперше, а надалі лише його, у PostgreSQL і його родині, HTTP-рушіях (ClickHouse, Elasticsearch і OpenSearch, CouchDB, Trino, InfluxDB та інших), Neo4j, Neptune, Redis і Cassandra. Якщо сертифікат змінюється, з'єднання переривається і показує обидва відбитки, з кнопкою **Довіряти новому сертифікату** для сервера, який його оновив; вкладка SSL/TLS показує закріплений відбиток із кнопкою **Забути**. Збережені з'єднання закріплюють сертифікат під час наступного підключення. `verify-ca` та параметри, що пропускають лише перевірку імені хоста, тепер перевіряють увесь ланцюжок за CA, а не приймають будь-який сертифікат. SQL Server, MySQL, MariaDB, MongoDB і SAP HANA зберігають власну поведінку своїх клієнтів.
- **Нові бази з'являються без повторного підключення:** база, створена командою `CREATE DATABASE` у запиті (або видалена, або перейменована), одразу з'являється в оглядачі та списках баз, а під час відкриття списку баз (міграція, порівняння, subset, резервні копії, дозволи, вибір бази в запиті…) він зчитується знову, тож база, створена іншим інструментом, теж з'являється.
- **Імпорт із SQL Server Management Studio:** окрім зареєстрованих серверів, DBine тепер імпортує сервери, які запам'ятовує діалог Connect в SSMS (його історію підключень), із логіном, базою та параметрами шифрування, з SSMS 18–20 і нових тек SSMS 21 та новіших. У macOS і Linux діалог вибору файлів тепер приймає файли `RegSrvr.xml`, `UserSettings.xml` і `.regsrvr` (та `dataSources.xml` із DataGrip); раніше можна було вибрати лише файли JSON.
- **Імпорт рядків підключення зберігає параметри шифрування:** вставлений або імпортований рядок тепер приносить свої параметри TLS у вигляді, властивому рушієві: `Encrypt` для SQL Server (зокрема `Strict`) і `HostNameInCertificate`, `sslmode` для PostgreSQL як записано (`require` більше не стає перевіреним підключенням), `ssl-mode` для MySQL і `useSSL` із Connector/J, `sslMode` для MariaDB, а також схеми `rediss://`, `bolt+s://` і `bolt+ssc://`. Рядок без параметрів TLS імпортується так, як підключався б його власний клієнт. Те саме стосується підключень, імпортованих з DBeaver, DataGrip та інших IDE JetBrains, DbGate і Azure Data Studio.
- **Помилки сертифіката в macOS і Windows:** сертифікат сервера, якому система не довіряє («The certificate was not trusted», «issued by an authority that is not trusted», «The target principal name is incorrect»), тепер розпізнається як такий, а повідомлення вказує, який параметр TLS змінити, замість загальної помилки TLS.
- **ClickHouse 22.8 і старіші:** підключення більше не завершується помилкою `Unknown setting http_write_exception_in_output_format`; DBine перестає запитувати цей параметр на серверах, де його немає.
- **Ноутбуки, експорт у Python:** підключення PostgreSQL, яке перевіряє сертифікат сервера, експортується з `sslmode=verify-full`, як це робить **Копіювати рядок підключення**, а не з `require`, який його не перевіряє.
- **HashiCorp Vault, безпека:** адреса Vault у джерела паролів має бути `https://`; звичайний `http://` приймається лише для Vault на цьому комп'ютері, як і для інших менеджерів секретів, тож токен Vault ніколи не передається мережею у відкритому вигляді.
