# 변경 사항

## [1.3.0] - 2026-10-30

### 새로운 기능
- **SSH 터널 프로필:** SSH 터널(서버, 배스천 호스트, 사용자, 인증)을 설정에서 한 번만 프로필로 저장하면 어느 연결에서든 선택할 수 있습니다. 각 연결은 자체 데이터베이스 서버를 유지합니다. 프로필을 수정하면 이를 사용하는 모든 연결에 다음 연결 시 적용되며, 연결의 현재 터널을 프로필로 저장할 수 있고, 프로필의 비밀 정보는 시스템 키체인에 보관됩니다.
- **마우스를 올리면 테이블 열 표시:** SQL 편집기에서 테이블 이름 위에 포인터를 올리면 각 열의 타입, null 허용 여부, 기본 키, 주석과 함께 열이 표시됩니다. 모든 엔진에서 지원됩니다.

### 개선
- **Claude Code 및 Codex를 사용하는 AI 어시스턴트:** 같은 연결의 다른 데이터베이스에 대해 질문하면 어시스턴트가 탭의 데이터베이스를 전환하지 않고 해당 테이블과 열을 읽습니다. 이 모델들은 지금도 테이블 행을 받지 않습니다.

### 수정
- **Linux의 SAP HANA, 보안:** 쿼리를 취소할 때 세션이 신뢰할 수 있는 인증서 폴더를 삭제한 뒤에는 더 이상 그 폴더를 읽지 않습니다. 이 순간을 같은 컴퓨터의 다른 사용자가 자신의 인증 기관을 심는 데 악용할 수 있었습니다.
- **보안, 종속성:** `ctutils`와 `crypto-bigint`를 상수 시간 관련 수정이 포함된 버전 이상으로 업데이트했습니다.
- **매우 긴 텍스트의 Excel 내보내기:** Excel 한도보다 긴 셀에 이모지 같은 문자가 들어 있어도 내보내기가 중단되지 않고 다시 한도에 맞게 잘립니다.
- **Trino 및 Presto, 보안:** 실제 어떤 스키마보다 깊게 중첩된 열 타입을 가진 테이블에서 데이터를 복사하거나 내보내도 더 이상 DBine이 비정상 종료되지 않습니다. 1.2.2에서 추가된 깊이 제한이 이제 이 경로에도 적용됩니다.

[@dylanwu](https://github.com/dylanwu) 님께 감사드립니다. 상세한 제보 덕분에 이번 버전의 새로운 기능 세 가지가 만들어졌습니다.

## [1.2.2] - 2026-10-28

### 수정
- **보안: ZIP 처리의 치명적인 취약점을 수정했습니다.** 10월 28일, DBine이 ZIP 기반 파일(Excel 가져오기 및 내보내기, AI 어시스턴트 내장 모델 다운로드)을 읽고 쓰는 데 사용하는 라이브러리 `zip`에서 치명적인 취약점이 공개되었습니다([GHSA-m665-v7pm-7grj](https://github.com/advisories/GHSA-m665-v7pm-7grj)). 특수하게 제작된 아카이브는 읽는 방식에 따라 서로 다른 내용을 보여 줄 수 있었습니다. 이 버전은 DBine의 모든 부분을 수정된 라이브러리로 전환했습니다. 1.2.1 이후 몇 시간 만에 출시되는 것은 오직 이 때문이므로 업데이트를 권장합니다.
- **Trino 및 Presto, 보안:** 실제 스키마보다 훨씬 깊게 중첩된 열 유형(악의적인 서버가 보낼 수 있음)은 단계별로 구문 분석하지 않고 받은 그대로 표시되므로 더 이상 DBine이 충돌하지 않습니다.

## [1.2.1] - 2026-10-28

### 수정
- **열 자동 완성이 작성 중인 쿼리를 따릅니다:** 편집기가 커서 위치의 문이 읽는 테이블, CTE, 서브쿼리의 열만 제안하며, 파일의 다른 문의 열은 제안하지 않습니다. 두 테이블이 공유하는 열은 테이블마다 한 번씩 제안되고, 별칭이 레이블로 표시되며, 한정된 형태(`c.customer_id`)로 삽입됩니다. CTE나 파생 테이블의 열은 쿼리 안과 그 별칭 뒤에서 제안됩니다.
- **행과 struct의 필드 이름:** Trino와 Presto의 `ROW` 값, PostgreSQL 복합 타입, Arrow Flight SQL struct가 각 필드를 이름과 함께 JSON으로 표시합니다. 중첩된 행, 행 배열, 값이 행인 맵에서도 마찬가지입니다(`[[42,[["demo-product",2]],null]]` 대신 `[{"customer_id":42,"items":[{"product_name":"demo-product","quantity":2}],"note":null}]`). `null`, 빈 문자열, 빈 배열은 계속 구분됩니다. ClickHouse 이름 있는 튜플은 선언된 필드 순서를 유지합니다.
- **VIEW DEFINITION 권한이 없는 SQL Server 로그인으로 마이그레이션:** 원본 로그인이 테이블은 읽을 수 있지만 정의는 읽을 수 없는 경우(Azure SQL에서 흔함) 마이그레이션 스크립트가 `CHECK ()`를 작성해 "Incorrect syntax near ')'" 오류로 실패했고, 열 기본값도 알리지 않고 버렸습니다. 이제 이러한 CHECK, 기본값, 계산식은 스크립트에서 제외되며, 미리보기와 실행 보고서 맨 위에 각각 이유와 DBine이 읽을 수 있게 하는 `GRANT VIEW DEFINITION`과 함께 나열됩니다. 생성된 스크립트와 스키마 동기화도 이를 알리며, 원본이 자체 CHECK를 읽지 못했다는 이유로 동기화가 대상의 CHECK를 삭제하지 않습니다. 이제 빈 CHECK나 DEFAULT를 작성하는 엔진은 없습니다.

## [1.2.0] - 2026-10-27

### 새로운 기능
- **우크라이나어 및 폴란드어:** DBine과 휴대폰 앱이 Українська와 Polski로 제공되며, 서버 메시지와 AI 어시스턴트도 포함됩니다. **설정 › 일반 › 언어**에서 언어를 선택할 수 있으며, 선택하지 않으면 DBine이 시스템 언어를 따릅니다.
- **인도네시아어:** DBine과 휴대폰 앱이 Bahasa Indonesia로 제공되며, 서버 메시지와 AI 어시스턴트도 포함됩니다. **설정 › 일반 › 언어**에서 언어를 선택할 수 있으며, 선택하지 않으면 DBine이 시스템 언어를 따릅니다.

### 개선
- **데이터베이스 간 자동 완성:** 하나의 쿼리가 같은 연결의 다른 데이터베이스를 읽을 수 있는 엔진(ClickHouse, MySQL 및 MariaDB, SQL Server, Snowflake, Databricks, Trino, BigQuery, Oracle 등)에서 편집기가 다른 데이터베이스의 이름, `other_db.` 뒤의 테이블, 테이블 또는 별칭 뒤의 열을 제안하며, 데이터베이스 간 조인에서도 동일합니다. 각 데이터베이스의 테이블은 그 이름과 점을 처음 입력할 때 읽어 옵니다.
- **DuckDB 엔진을 2.0.0으로 업데이트:** 로컬 DuckDB 파일과 노트북의 DataFrame SQL이 이제 DuckDB 2.0.0(이전 1.5.5)에서 실행됩니다. 새 데이터베이스 파일은 DuckDB 2.0의 저장 형식을 사용하므로 이전 DuckDB 버전에서는 열 수 없습니다. 기존 파일은 계속 열리며, 해당 파일을 만든 버전에서도 읽을 수 있습니다.
- **SQL Server, PostgreSQL, MySQL의 연결 암호화:** 연결 양식에 각 엔진의 도구가 사용하는 이름으로 해당 엔진 고유의 TLS 옵션이 표시됩니다. SQL Server와 Azure SQL은 `Encrypt`(Optional, Mandatory, Strict), `TrustServerCertificate`, `ServerCertificate`, `HostNameInCertificate`, PostgreSQL과 그 계열은 `sslmode`와 `sslrootcert`, MySQL과 그 계열은 `ssl-mode`와 `ssl-ca`, MariaDB와 OceanBase는 `ssl`, `ssl-verify-server-cert`, `ssl-ca`입니다. 새 연결은 암호화되고 서버 인증서를 검증하며, 각 설정은 끌 수 있습니다. 저장된 연결은 이전과 똑같이 동작합니다. SSH 터널을 통할 때는 인증서를 실제 서버의 이름으로 검증하고, 인증서 오류가 발생하면 변경할 옵션을 알려 줍니다. MySQL의 `PREFERRED`는 서버가 TLS를 제공하지 않을 때에만, 비밀번호를 보내기 전에 암호화되지 않은 연결로 전환됩니다.
- **InfluxDB, IoTDB, ksqlDB, TDengine, Phoenix, Arrow Flight SQL 및 클라우드 서비스의 연결 암호화:** 연결 양식에 각 엔진 고유의 TLS 옵션이 표시됩니다. InfluxDB 1은 `ssl`과 `unsafeSsl`, InfluxDB 2는 `skip-verify`가 붙은 URL 스키마, InfluxDB 3은 `tls-no-verify`와 `tls-ca`, IoTDB와 TimechoDB는 `use_ssl`과 `ca_certs`, ksqlDB는 `useTls`, `verifyHost`, `trustStore`, TDengine은 `useSSL`, Phoenix와 Avatica는 URL 스키마, `hostname_verification`, `truststore`, Flight SQL은 `useEncryption`과 `tlsRootCerts`, Cosmos DB 에뮬레이터는 `DisableServerCertificateValidation`입니다. 엔진의 도구에 검증을 건너뛰거나 CA 파일을 지정하는 이름이 없는 경우에는 curl의 `insecure`와 `cacert`를 사용합니다. 새 연결은 암호화되고 서버 인증서를 검증하며, 각 설정은 끌 수 있습니다. 저장된 연결은 이전과 똑같이 동작합니다. SSH 터널을 통할 때는 인증서를 실제 서버의 이름으로 검증하고, 인증서 오류나 TLS를 지원하지 않는 서버는 그대로 보고됩니다. BigQuery, Spanner, DynamoDB, Athena, Snowflake, Databricks, libSQL은 항상 검증된 HTTPS를 사용합니다. 단, `http://`로 입력한 에뮬레이터 엔드포인트는 예외입니다.
- **키보드와 화면 낭독기:** 보이는 포커스 링이 키보드 위치를 알려 줍니다. 목록 행, 카드, 정렬 가능한 헤더, 접을 수 있는 섹션은 Tab으로 이동하고 Enter 또는 Space로 사용할 수 있습니다. 컨텍스트 메뉴는 화살표 키로 작동합니다. 아이콘만 있는 버튼에 화면 낭독기가 읽어 주는 이름이 생겼습니다. 쿼리 결과(완료 또는 오류로 실패)가 안내됩니다. 시스템에서 동작 줄이기를 요청하면 애니메이션이 멈춥니다. 두 테마 모두에서 보조 텍스트의 대비가 높아졌습니다.

### 수정
- **“확인 안 함”이 이제 서버 인증서를 고정합니다, 보안:** 서버 인증서를 확인하지 않는 연결(`sslmode=require`, `insecure`, `bolt+ssc`, `validate=false`…)은 서버가 처음 제시한 인증서를 수락하고 그 후에는 해당 인증서만 수락합니다. 적용 대상은 PostgreSQL과 그 계열, HTTP 엔진(ClickHouse, Elasticsearch와 OpenSearch, CouchDB, Trino, InfluxDB 등), Neo4j, Neptune, Redis, Cassandra입니다. 인증서가 바뀌면 연결이 중단되고 두 지문이 표시되며, 서버가 인증서를 갱신한 경우 **새 인증서 신뢰**를 사용할 수 있습니다. SSL/TLS 탭에는 고정된 지문이 표시되며 **잊기**를 사용할 수 있습니다. 저장된 연결은 다음 연결 시 고정됩니다. `verify-ca`와 호스트 이름만 건너뛰는 옵션은 이제 아무 인증서나 수락하는 대신 전체 체인을 CA와 대조해 확인합니다. SQL Server, MySQL, MariaDB, MongoDB, SAP HANA는 각 클라이언트 고유의 동작을 유지합니다.
- **다시 연결하지 않아도 새 데이터베이스 표시:** 쿼리에서 `CREATE DATABASE`로 만든(또는 삭제하거나 이름을 바꾼) 데이터베이스가 탐색기와 데이터베이스 목록에 즉시 나타나며, 데이터베이스 목록(마이그레이션, 비교, subset, 백업, 권한, 쿼리의 데이터베이스 선택기 등)을 열면 다시 읽어 오므로 다른 도구에서 만든 데이터베이스도 표시됩니다.
- **SQL Server Management Studio에서 가져오기:** 등록된 서버 외에도 SSMS의 연결 대화상자가 기억하는 서버(연결 기록)를 로그인, 데이터베이스, 암호화 설정과 함께 가져옵니다. SSMS 18~20과 SSMS 21 이상의 새 폴더를 지원합니다. macOS와 Linux에서는 파일 대화상자가 이제 `RegSrvr.xml`, `UserSettings.xml`, `.regsrvr` 파일(및 DataGrip의 `dataSources.xml`)을 허용합니다. 이전에는 JSON 파일만 선택할 수 있었습니다.
- **연결 문자열 가져오기에서 암호화 설정 유지:** 붙여넣거나 가져온 문자열이 이제 각 엔진 고유의 TLS 옵션을 그대로 가져옵니다. SQL Server의 `Encrypt`(`Strict` 포함)와 `HostNameInCertificate`, PostgreSQL의 `sslmode`는 적힌 그대로(`require`가 더 이상 검증된 연결이 되지 않음), MySQL의 `ssl-mode`와 Connector/J의 `useSSL`, MariaDB의 `sslMode`, 그리고 `rediss://`, `bolt+s://`, `bolt+ssc://` 스키마입니다. TLS 설정이 없는 문자열은 해당 클라이언트가 직접 연결하는 방식대로 가져옵니다. DBeaver, DataGrip 및 기타 JetBrains IDE, DbGate, Azure Data Studio에서 가져온 연결에도 동일하게 적용됩니다.
- **macOS와 Windows의 인증서 오류:** 시스템이 신뢰하지 않는 서버 인증서("The certificate was not trusted", "issued by an authority that is not trusted", "The target principal name is incorrect")가 이제 그대로 인식되며, 일반적인 TLS 오류 대신 변경할 TLS 옵션을 메시지로 알려 줍니다.
- **ClickHouse 22.8 이하:** 연결이 더 이상 `Unknown setting http_write_exception_in_output_format` 오류로 실패하지 않습니다. DBine은 해당 설정이 없는 서버에는 그 설정을 요청하지 않습니다.
- **노트북, Python 내보내기:** 서버 인증서를 검증하는 PostgreSQL 연결은 검증하지 않는 `require` 대신 **연결 문자열 복사**와 같은 `sslmode=verify-full`로 내보냅니다.
- **HashiCorp Vault, 보안:** 비밀번호 소스의 Vault 주소는 `https://`여야 합니다. 다른 시크릿 관리자와 마찬가지로 일반 `http://`는 이 컴퓨터의 Vault에만 허용되므로, Vault 토큰이 네트워크에서 평문으로 전송되는 일은 없습니다.

## [1.1.0] - 2026-10-21

### 새로운 기능
- **클라우드 동기화 상태를 한눈에:** 상태 표시줄에 초록색 점과 함께 **동기화됨**, 변경 사항이 업로드를 기다리는 동안에는 호박색으로 **업로드 대기**, 오류가 나면 빨간색이 표시됩니다. 마우스를 올리면 마지막 동기화 시각이 보이고, 클릭하면 동기화 설정이 열립니다.
- **연결 문자열 복사:** 연결을 마우스 오른쪽 버튼으로 클릭하거나(또는 연결 양식의 버튼을 사용해) **연결 문자열 복사…** 를 선택하면 해당 엔진에 맞는 URI, ADO.NET, JDBC, SQLAlchemy, ODBC, libpq, Node.js, Go 형식의 연결 문자열을 모든 데이터베이스에 대해 TLS 및 로그인 설정과 함께 얻을 수 있습니다. 비밀번호는 포함되지 않으며(`${DB_PASSWORD}` 자리 표시자) **비밀번호 포함** 을 켠 경우에만 복사할 때 가져오고, 1분 뒤에도 클립보드에 남아 있으면 지워집니다.
- 예약 작업에 **메시지 보내기** 단계가 추가되었습니다. 실행 결과를 Microsoft Teams, Slack, Telegram 또는 ntfy에 게시할 수 있으며, 작업 변수(`{results}`는 각 단계가 수행한 내용을 나열합니다), 이메일 단계와 같은 **조건…**, **테스트** 버튼을 지원합니다. 웹후크 URL과 토큰은 작업이 아닌 키체인에 저장되며, 메시지는 해당 서비스 자체 서버로만 HTTPS를 통해 전송됩니다.

### 수정
- **SSH 터널, 보안:** SSH 라이브러리를 업데이트하여 두 가지 권고 사항(SSH 에이전트를 통한 서비스 거부 CVE-2026-111061 및 CVE-2026-111062)을 수정했습니다.
- **RSA 키, 보안:** RSA 키를 사용한 SSH 로그인과 Zoho Vault 및 Bitwarden 조직 키 열기를 이제 AWS-LC에서 일정한 시간으로 실행하므로, RSA 라이브러리의 타이밍 누출(RUSTSEC-2023-0071, "Marvin")은 더 이상 해당되지 않습니다. RSA 키는 SHA-256 또는 SHA-512로 서명하며, SHA-1(`ssh-rsa`)만 허용하는 서버에서는 Ed25519 또는 ECDSA 키 또는 SSH 에이전트가 필요합니다.
- **TLS, 보안:** DBine과 33개 드라이버의 TLS 라이브러리와 인증서 검사를 업데이트했습니다(RUSTSEC-2026-0346~0349 및 0381~0383). 이제 더 이상 신뢰하지 않는 인증 기관의 인증서는 거부됩니다. 업데이트된 드라이버는 자동으로 다운로드됩니다.
- **내장 AI 엔진:** 엔진 압축을 풀 때 파일의 읽기, 쓰기, 실행 권한만 유지됩니다.
- **예약 작업, 보안:** `{results}`와 `{alerts}`는 이제 메일과 메시지의 텍스트만 채웁니다. 스크립트의 SQL, 파일이나 폴더 이름, 주소, 첨부 파일 경로에는 더 이상 적용되지 않으므로, 조작된 데이터를 그대로 보여 주는 데이터베이스 오류가 SQL이나 경로로 바뀔 수 없습니다.
- **예약 작업 메시지:** 메시지나 메일의 `{results}`와 `{alerts}`가 항상 스페인어로 나오지 않고 DBine의 인터페이스 언어로 표시됩니다. DBine을 닫은 채 작업이 실행될 때도 마찬가지입니다.
- **노트북, 큰 DataFrame SQL 결과:** **고급 내보내기… › 모두** 가 표시된 행뿐 아니라 전체 결과를 기록합니다. 셀의 SQL은 마지막 실행에서 읽은 DataFrame을 대상으로 DuckDB에서 다시 실행되며, 파일을 다시 읽거나 소스를 다시 쿼리하지 않습니다. 차트는 처음부터 전체 결과로 계산되며 끌 수도 있습니다. 결과가 잘린 경우 정렬과 **모두 복사** 가 불러온 행에만 적용된다는 안내도 그리드에 표시됩니다.

- **DataFrame SQL 셀의 자동 완성:** 위쪽 셀이 테이블로 제안되며(아직 실행하지 않은 셀도 포함), `name.` 또는 별칭 뒤와 select 목록에서 해당 열이 제안됩니다. FROM과 JOIN 뒤에는 DuckDB의 파일 리더도 제안됩니다. 리더를 선택하면 커서가 따옴표 사이에 놓이고, **파일 선택…**으로 파일 대화 상자를 열 수 있습니다. 노트북이 새로 고쳐지는 동안 FROM 뒤의 테이블 목록이 저절로 닫히지도 않습니다.
- **지도 보기:** 지오메트리 열(PostGIS, MySQL, SQL Server, SQLite/SpatiaLite, DuckDB, MongoDB, Elasticsearch 등) 또는 위도/경도 열이 있는 결과를 지도에 표시할 수 있습니다. 지도는 내장된 오프라인 세계 지도 위에 이 컴퓨터에서 그려집니다. 상세한 온라인 지도 타일은 **설정 › 지도**에서 켤 수 있으며, 이 경우 제공업체는 보고 있는 영역은 알 수 있지만 데이터는 알 수 없습니다.
- **지도에서 Oracle 지원:** SDO_GEOMETRY 열이 이제 테이블 데이터와 직접 작성한 쿼리 모두에서 결과 지도에 표시됩니다(서버에서 SRID와 함께 WKT로 변환). 이 셀은 그리드에서 읽기 전용입니다.
- **데이터 파일 바로 열기:** SQLite, DuckDB, CSV, TSV, Parquet, JSON, Excel 파일을 더블 클릭하거나 "DBine으로 열기", 창에 끌어 놓기, **파일 › 파일 열기…**(Cmd/Ctrl+O)로 열 수 있습니다. 각 파일은 임시 연결로 열리며 **연결 저장**으로 보관할 수 있고, 데이터 파일은 처음 1,000행을 바로 보여 줍니다.
- **명령 팔레트:** Cmd/Ctrl+Shift+P로 모든 작업을 찾아 실행할 수 있으며, 현재 엔진이 지원하는 것만 표시됩니다. **이동…**(Cmd/Ctrl+P)으로 연결, 데이터베이스, 테이블, 뷰, 루틴, 저장된 쿼리, 열려 있는 탭으로 이동할 수 있습니다. 팔레트의 모든 작업에 고유한 단축키를 지정할 수도 있습니다.
- **관련 행으로 이동:** 테이블 데이터나 쿼리 결과에서 **참조된 행으로 이동**(또는 Cmd/Ctrl+클릭)을 선택하면 해당 외래 키로 필터링된 부모 테이블이 열리고, **이 행을 참조하는 행**을 선택하면 그 값으로 필터링된 각 자식 테이블이 열립니다(복합 키 포함). 외래 키가 있는 모든 엔진에서 사용할 수 있습니다.
- **SQL 노트북:** **파일 › 새 노트북**으로 노트북을 엽니다. 어떤 연결에서든 실행되는 SQL 셀이 각각 결과와 차트를 아래에 보관하며, 설명을 위한 텍스트 셀도 사용할 수 있습니다. 표준 Jupyter `.ipynb`로 저장되어 GitHub, VS Code, Jupyter에서 표시되며 Azure Data Studio와 Jupyter `%%sql` 노트북에서도 열 수 있습니다. 파일에는 각 결과의 미리 보기(셀당 100행과 1MB, **설정 › 노트북**에서 변경)가 전체 행 수, 시간, 소요 시간과 함께 저장되며 연결 정보나 비밀번호는 저장되지 않습니다. 프로젝트 안에서는 켜지 않는 한 노트북이 결과 없이 저장됩니다. 어시스턴트는 행을 보지 않고도 결과를 설명하거나, 다음 셀 또는 큰 쿼리의 그룹화된 버전을 제안할 수 있습니다. HTML 또는 Markdown으로 내보낼 수 있습니다.
- **전체 결과에 대한 차트:** 차트는 그리드에 불러온 행만이 아니라 결과의 모든 행을 기준으로 계산됩니다. SQL 엔진에서는 그룹화를 서버에서 실행하고, 노트북의 DataFrame SQL 셀에서는 DuckDB가, 그 밖의 엔진에서는 DBine이 처리합니다.
- **더 많은 차트 종류:** 히스토그램, 히트맵, 상자 수염 그림(수염과 이상치 포함), 막대와 선 조합, KPI(전체 결과의 합계).
- **노트북 셀당 여러 차트:** 노트북 셀은 결과에 대한 차트를 둘 이상 표시할 수 있으며, 지도가 사용하는 소스도 기억합니다.
- **노트북 내보내기에 차트 포함:** HTML 또는 Markdown으로 내보낸 노트북에 차트가 이미지로 포함됩니다.
- **노트북에서 서로 다른 데이터베이스의 결과 조인:** 각 셀의 결과는 셀 이름(헤더에 표시되며 편집 가능)을 가진 DataFrame이 되고, **DataFrame SQL** 셀은 연결 없이 위쪽 DataFrame을 테이블로 보고 DuckDB의 SQL로 조회하고 조인합니다. 그래서 하나의 셀에서 PostgreSQL 결과를 SQL Server, MongoDB 결과와 조인할 수 있습니다. 파일을 쓰거나 네트워크에 접근할 수 없는 메모리 내 DuckDB 데이터베이스에서 실행되며 노트북을 닫으면 삭제됩니다. 각 소스의 행은 이 세션에서의 실행 결과 또는 해당 소스의 연결에서 읽기 전용으로 다시 실행한 쿼리에서 가져옵니다(DataFrame당 최대 1,000,000행, **설정 › 노트북**에서 변경).
- **예약된 보고서로서의 노트북:** 예약된 작업은 DBine을 닫은 상태에서 노트북을 실행하고(**노트북 실행**), 실행된 사본을 저장하여 HTML 또는 Markdown으로 내보낼 수 있으며, 다음 **메일 보내기** 단계에서 이를 첨부하거나 HTML 내보내기를 메일 본문으로 보낼 수 있습니다. 무인 실행 중에는 아무것도 묻지 않습니다. 해당 노트북에서 **항상 허용**한 파일만 읽고, 확인이 필요한 환경에서는 단계가 명시적으로 허용한 경우에만 실행하며, 데이터를 변경하는 셀은 작업의 승인에 포함됩니다. 예약된 내보내기에는 표가 포함되며, 차트는 앱에서 내보낼 때 포함됩니다.
- **DataFrame SQL 셀의 로컬 파일:** DataFrame SQL 셀은 컴퓨터의 CSV, Parquet, JSON 또는 NDJSON과 Excel 파일을 `read_csv`, `read_parquet`, `read_json`, `read_xlsx`로 읽을 수 있습니다(`data/*.csv` 같은 패턴과 파일 목록 포함). 지리 파일(GeoJSON, 보조 파일이 있는 Shapefile, GeoPackage, KML, GPX, FlatGeobuf)은 `st_read`로, SQLite 및 DuckDB 데이터베이스 파일의 테이블은 `sqlite_scan`과 `read_duckdb`로 읽습니다. 각각은 DataFrame이 되어 어떤 엔진의 셀 결과와도 조인할 수 있으며, 지오메트리는 `ST_Contains` 같은 공간 함수로 계속 사용할 수 있고 지도에도 표시됩니다. 파일은 읽기만 하고 쓰지 않습니다. 파일을 처음 읽기 전에 노트북이 묻습니다. 이번 실행에만 허용, 이 컴퓨터에서 이 노트북에 항상 허용(패턴은 새 파일도 포함), 또는 거부 중에서 선택할 수 있습니다. 자격 증명, 키, 셸 기록, 시스템 파일은 절대 읽지 않습니다. 지난 실행 이후 파일 내용이 바뀐 경우 결과에 그 사실이 표시됩니다. 설정 › 노트북에는 각 노트북이 읽을 수 있는 파일이 나열되며 삭제할 수 있습니다. 같은 리더로 웹(`https://`)과 Amazon S3, Google Cloud Storage, Azure Blob Storage(`s3://`, `gs://`, `az://`, `abfss://`, `s3://bucket/2026/*.parquet` 같은 패턴 포함)의 파일도 읽을 수 있으며, 승인 방식은 같고 서버가 먼저 표시됩니다. DBine이 직접 파일을 읽은 뒤 삭제되는 비공개 임시 폴더에 다운로드하며, 이 컴퓨터의 AWS, Google Cloud 또는 Azure 로그인을 사용합니다(AWS 프로필은 설정 › 노트북에서 선택 가능). 로컬 또는 사설 네트워크 주소에는 접근하지 않고, 다른 서버로의 리디렉션을 따르지 않으며, URL에 포함된 자격 증명도 받아들이지 않습니다. 다른 프로그램에서 열려 있는 GeoPackage에는 이제 `-wal`에 남아 있는 변경 사항도 포함됩니다.
- **노트북을 Python 노트북으로 내보내기:** **내보내기 › Python 노트북(.ipynb)**은 원본을 재현하는 Jupyter 노트북을 작성합니다. 연결마다 SQLAlchemy 엔진(또는 pymongo, redis처럼 엔진 고유의 Python 클라이언트)을 만들고, 각 쿼리 셀은 셀 이름의 pandas DataFrame으로 읽으며, DataFrame SQL 셀은 그 DataFrame 위에서 DuckDB로 실행하고, 텍스트 셀은 Markdown이 됩니다. 비밀번호와 토큰은 절대 내보내지 않습니다. 코드는 환경 변수에서 읽으며, 첫 번째 셀에 환경 변수와 설치할 패키지가 나열됩니다. 미리 보기를 포함하도록 선택하지 않으면 결과는 제외됩니다.
- **노트북에서 DataFrame을 테이블에 쓰기:** **쓰기 셀**(아무 셀 아래에서 **테이블에 쓰기…**로 추가)은 셀의 전체 결과를 SQL Server, PostgreSQL, MySQL, MariaDB, Oracle, SQLite, DuckDB, MongoDB 등의 테이블에 씁니다. 삽입, 키 기준 업데이트, 삽입 또는 업데이트, 테이블 내용 교체를 선택할 수 있으며, 열 매핑과 미리 보기가 있고 원하면 새 테이블도 만들 수 있습니다. 쓰기는 매번 먼저 확인하며 대상, 방식, 행 수를 보여 줍니다(운영 환경 연결에서는 테이블 이름을 입력해야 함). 트랜잭션을 지원하는 엔진에서는 하나의 트랜잭션으로 실행되며, 읽기 전용 연결에는 절대 쓰지 않습니다. 예약된 작업에서는 단계가 해당 셀, 테이블, 모드를 허용한 경우에만 쓰기 셀이 실행됩니다.
- **노트북 매개변수:** 노트북은 매개변수(텍스트, 숫자, 날짜, 날짜와 시간, 불리언 또는 고정 목록, 기본값 포함)를 정의할 수 있으며, 셀에서 `{{name}}`으로 사용합니다. 실행할 때 빠진 값을 묻고, 각 값은 데이터로 데이터베이스에 전달되며(드라이버가 바인딩하거나 엔진 자체 규칙에 따라 따옴표 처리), 모든 결과에는 그 결과를 만든 값이 표시됩니다.
- **5개 언어 추가:** DBine과 모바일 앱이 스페인어, 영어, 포르투갈어, 프랑스어, 이탈리아어에 더해 독일어, 러시아어, 중국어 간체, 일본어, 한국어를 지원합니다. 언어는 시스템 언어를 따르며 사용 중인 언어만 불러옵니다.

### 개선
- **macOS 서명:** macOS 앱이 Apple Developer ID로 서명되고 Apple의 공증을 받았으므로 "개발자를 확인할 수 없음" 경고나 터미널 명령 없이 열립니다. 서명된 버전을 처음 열면 DBine이 키체인의 키를 사용해도 되는지 macOS가 한 번 묻습니다. **항상 허용**을 선택하세요.
- **클라우드 로그인은 인스턴스의 인증서만 신뢰:** AWS IAM, Google Cloud IAM, Microsoft Entra로 로그인하는 연결과 인스턴스의 CA 파일을 사용하는 Cloud SQL 및 AlloyDB 연결은 이제 토큰이나 비밀번호를 보내기 전에 임의의 공개 인증서가 아니라 해당 CA(또는 Amazon의 RDS 번들)만 허용합니다. **서버 인증서 신뢰**가 켜져 있을 때 비밀번호를 평문으로 요구하는 서버는 이제 비밀번호를 받지 못하고 연결에 실패합니다.
- **Windows 서명:** Windows 설치 프로그램과 앱이 코드 서명 인증서로 서명되었으므로 Windows가 "알 수 없는 게시자" 대신 DBine의 게시자를 표시합니다.

### 수정
- **서버 모니터:** 수치, 표, 설명이 모든 엔진에서 번역되어, 일부 레이블이 스페인어로 표시되던 문제가 해결되었습니다.
- **AI 어시스턴트와 최적화 도구:** 모델에 전달하는 지시문이 인터페이스 언어로 작성되므로, 로컬 모델이 스페인어가 아니라 해당 언어로 답변합니다. 모델에 무엇을 보냈는지 알려 주는 줄도 번역되었습니다.
