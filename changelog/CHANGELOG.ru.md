# Изменения

## [1.1.0] - 2026-10-21

### Новое
- **Лицензия:** теперь DBine распространяется по лицензии Apache 2.0 (до 1.0.0 была MIT). Файл NOTICE сопровождает любое распространение, а лицензия не даёт права использовать названия и логотипы DBine и AddLayer.
- **Состояние облачной синхронизации с первого взгляда:** в строке состояния отображается **Синхронизировано** с зелёной точкой, **Ожидает** оранжевым, пока изменение ждёт отправки, и красный цвет при ошибке; наведите указатель, чтобы увидеть время последней синхронизации, и нажмите, чтобы открыть настройки синхронизации.
- **Копирование строки подключения:** щёлкните подключение правой кнопкой мыши (или воспользуйтесь кнопкой в его форме) и выберите **Копировать строку подключения…**, чтобы получить её как строку URI, ADO.NET, JDBC, SQLAlchemy, ODBC, libpq, Node.js или Go — те, что подходят его движку, — для любой базы данных, с настройками TLS и входа. Пароль не включается (вместо него заполнитель `${DB_PASSWORD}`), если не включить **Включить пароль**; тогда он запрашивается в момент копирования и через минуту удаляется из буфера обмена, если всё ещё там.
- **Шаг «Отправить сообщение»** в запланированных задачах: отправляйте итог выполнения в Microsoft Teams, Slack, Telegram или ntfy с переменными задачи (`{results}` перечисляет, что сделал каждый шаг), с условием **Только если…** как в шаге электронной почты и кнопкой **Проверить**. URL вебхука и токены хранятся в связке ключей, а не в задаче, и сообщения отправляются только по HTTPS на серверы самого сервиса.

### Исправления
- **SSH-туннели, безопасность:** библиотека SSH обновлена, чтобы исправить два бюллетеня безопасности (CVE-2026-111061 — отказ в обслуживании через агент SSH, и CVE-2026-111062).
- **TLS, безопасность:** библиотека TLS и её проверки сертификатов обновлены в DBine и в 33 драйверах (RUSTSEC-2026-0346–0349 и 0381–0383), поэтому сертификаты удостоверяющих центров, которым больше не доверяют, отклоняются. Обновлённые драйверы загружаются сами.
- **Встроенный движок ИИ:** при распаковке движка сохраняются только права файлов на чтение, запись и выполнение.
- **Запланированные задачи, безопасность:** `{results}` и `{alerts}` подставляются только в текст писем и сообщений. SQL скрипта, имя файла или папки, адрес и путь к вложению их больше не принимают, поэтому ошибка базы данных, повторяющая подделанные данные, не может превратиться в SQL или путь.
- **Сообщения запланированных задач:** `{results}` и `{alerts}` в сообщении или письме выводятся на языке интерфейса DBine, а не всегда на испанском, в том числе когда задача выполняется при закрытом DBine.
- **Ноутбуки, большие результаты DataFrame SQL:** **Расширенный экспорт… › Все** записывает весь результат, а не только показанные строки. SQL ячейки снова выполняется в DuckDB над DataFrame, прочитанными при её последнем запуске, без повторного чтения файлов и повторных запросов к источникам. Её диаграммы сразу считаются по всему результату, это можно отключить. Если результат обрезан, таблица также сообщает, что сортировка и **Копировать всё** относятся только к загруженным строкам.

## [1.0.0] - 2026-10-19

### Новое
- **Светлая тема:** светлая тема и параметр **Как в системе** (по умолчанию), который следует за вашей ОС при её изменении; масштаб интерфейса с помощью Cmd/Ctrl + «+», «−», «0» или колеса мыши, а также отдельные размеры шрифта для редактора и таблицы результатов — в разделе **Настройки › Основные**.
- **Режим Vim и собственные сочетания клавиш:** режим Vim для редактора SQL (Настройки › Основные); любое сочетание клавиш можно изменить в разделе **Настройки › Сочетания клавиш** — с поиском, сбросом и предупреждениями о конфликтах.
- **Разделённый редактор:** до трёх групп редактора рядом или одна над другой (меню вкладки, кнопка в панели вкладок или Cmd/Ctrl+\); вкладки можно перетаскивать между группами или на правую либо нижнюю половину группы, чтобы разделить её. Раскладка восстанавливается после перезапуска.
- **Облачный вход для управляемых баз данных:** подключения PostgreSQL и MySQL к Amazon RDS и Aurora, Google Cloud SQL и AlloyDB, а также Azure Database могут входить через **AWS IAM**, **Google Cloud IAM** или **Microsoft Entra ID**. Перед каждым подключением DBine создаёт новый токен из вашего профиля AWS (включая SSO), gcloud или az, так что больше не нужно вставлять токены, которые истекают через 15 минут, а **Проверить** показывает, какая учётная запись вошла.
- **Пароли из команды или менеджера секретов:** любое секретное поле любого движка, а также пароль и парольная фраза ключа SSH-туннеля могут получать значение из команды, 1Password, HashiCorp Vault, AWS Secrets Manager, Azure Key Vault или Google Secret Manager. Оно запрашивается при каждом подключении и хранится только в памяти; есть вариант с ключом JSON и проверка для каждого поля, показывающая только длину. Настройка команды или менеджера секретов, пришедшая из импорта или восстановленной резервной копии, выполняется только после того, как вы подтвердите её на этом компьютере.
- **KeePass и Zoho Vault как источники паролей:** любое секретное поле (и поле SSH-туннеля) может брать значение из записи базы KeePass (.kdbx, которую DBine читает сам; мастер-пароль из связки ключей, запрашивается при подключении или из команды; необязательный файл ключа) или из секрета Zoho Vault (любой дата-центр, расшифровывается на вашем компьютере вашей мастер-фразой); при желании пользователь подключения берётся из той же записи.
- **Учётные данные базы из Vault, CyberArk и Delinea как источники паролей:** пароли подключений могут поступать из движка секретов баз данных HashiCorp Vault (учётные данные создаются для подключения, продлеваются, пока оно открыто, и отзываются при закрытии; для Vault также вход через AppRole), из CyberArk Conjur, Central Credential Provider от CyberArk (с клиентскими сертификатами) и Delinea Secret Server.
- **Bitwarden, Bitwarden Secrets Manager и AWS Parameter Store как источники паролей:** любое секретное поле (и поле SSH-туннеля) может брать значение из элемента Bitwarden, личного или организации, на bitwarden.com, bitwarden.eu или вашем собственном сервере, расшифровываемого на вашем компьютере мастер-паролем; из секрета Bitwarden Secrets Manager (с токеном доступа машинной учётной записи) или из параметра AWS Systems Manager (SecureString, String или один элемент StringList); при желании — с ключом JSON и пользователем подключения из того же элемента.
- **Сначала учётные данные и обзор менеджера секретов:** форма подключения сначала спрашивает **Учётные данные**: хранить пароль в связке ключей, запрашивать его каждый раз либо брать пользователя и пароль из командной строки или менеджера секретов, поля которого их заменяют. Кнопка **Обзор** показывает записи менеджера и названия их полей, чтобы выбирать их, а не вводить ссылки; она показывает только имена, никогда не значения.
- **Пользователь и пароль из записи:** если учётные данные берутся из KeePass, Bitwarden, 1Password, Zoho Vault, Delinea или CyberArk CCP, и пользователь, и пароль поступают из записи, а в **Дополнительных параметрах** можно выбрать другие поля из собственного списка записи. Каждый источник сначала запрашивает свой вход, а запись — последней, и Обзор готов, как только это заполнено.
- **Учётные записи Zoho Vault — подключить один раз:** пошаговый мастер **Подключить Zoho Vault** проведёт вас по консоли Zoho, найдёт ваш дата-центр и проверит мастер-фразу; после этого любому подключению достаточно выбрать учётную запись. Учётные записи остаются на этом компьютере и управляются в разделе **Настройки › Менеджеры секретов**.
- **Учётные записи для каждого менеджера секретов:** Bitwarden, Bitwarden Secrets Manager, HashiCorp Vault и OpenBao, Delinea, CyberArk Conjur и Central Credential Provider, 1Password, AWS, Azure Key Vault, Google Secret Manager и KeePass теперь подключаются один раз в **Настройки › Менеджеры секретов** с помощью пошагового мастера, который объясняет, где находится каждое значение, проверяет учётную запись в реальном времени и показывает, кто вошёл; после этого любому подключению достаточно выбрать учётную запись, а учётные данные отправляются только на собственный сервер этого менеджера.
- **Выбор тенантов Azure:** мастер учётной записи Azure Key Vault показывает список ваших тенантов Microsoft Entra (по-прежнему можно ввести свой), а если вы не вошли в выбранный тенант, он показывает команду `az login --tenant`, которую можно скопировать.
- **Автодополнение в ячейках DataFrame SQL:** ячейки выше предлагаются как таблицы (даже ещё не выполненные), со своими столбцами после `name.` или псевдонима и в списке select, а также функции чтения файлов DuckDB после FROM и JOIN; при выборе функции курсор встаёт между её кавычками, где **Выбрать файл…** открывает диалог выбора файла. Список таблиц после FROM больше не закрывается сам, пока блокнот обновляется.
- **Вид карты:** результаты со столбцами геометрии (PostGIS, MySQL, SQL Server, SQLite/SpatiaLite, DuckDB, MongoDB, Elasticsearch и другие) или со столбцами широты/долготы можно показать на карте, которая рисуется на этом компьютере поверх встроенной офлайн-карты мира. Подробные онлайн-тайлы карты можно включить в разделе **Настройки › Карты**; тогда поставщик видит, какую область вы просматриваете, но никогда не данные.
- **Oracle на карте:** столбцы SDO_GEOMETRY теперь отображаются на карте результатов — и в данных таблицы, и в ваших собственных запросах (на сервере преобразуются в WKT вместе с их SRID); эти ячейки в таблице доступны только для чтения.
- **Открытие файлов с данными напрямую:** файлы SQLite, DuckDB, CSV, TSV, Parquet, JSON и Excel открываются двойным щелчком или через «Открыть с помощью DBine», перетаскиванием в окно или через **Файл › Открыть файл…** (Cmd/Ctrl+O). Каждый открывается как временное подключение, которое можно сохранить через **Сохранить подключение**, а файлы с данными сразу показывают первые 1000 строк.
- **Палитра команд:** Cmd/Ctrl+Shift+P находит и выполняет любое действие, показывая только то, что поддерживает текущий движок, а **Перейти к…** (Cmd/Ctrl+P) переходит к подключениям, базам данных, таблицам, представлениям, процедурам, сохранённым запросам и открытым вкладкам. Любому действию палитры можно также назначить собственное сочетание клавиш.
- **Переход к связанным строкам:** в данных таблицы или результатах запроса **Перейти к связанной строке** (или Cmd/Ctrl+щелчок) открывает родительскую таблицу, отфильтрованную по этому внешнему ключу, а **Строки, которые на неё ссылаются** открывает каждую дочернюю таблицу, отфильтрованную по значению, включая составные ключи. Во всех движках с внешними ключами.
- **Блокноты SQL:** **Файл › Новый блокнот** открывает блокнот: ячейки SQL, которые выполняются на любом подключении и хранят под собой результат и диаграмму, и текстовые ячейки для пояснений. Он сохраняется как стандартный Jupyter `.ipynb`, который показывают GitHub, VS Code и Jupyter и который открывают также Azure Data Studio и блокноты Jupyter `%%sql`. Файл хранит предпросмотр каждого результата (100 строк и 1 МБ на ячейку, в разделе **Настройки › Блокноты**) с общим числом строк, временем и длительностью, но никогда не данные подключения и не пароли; внутри проекта блокноты сохраняются без результатов, если вы не включите их. Ассистент может объяснить результат, предложить следующую ячейку или сгруппированный вариант большого запроса, не видя строк. Экспорт в HTML или Markdown.
- **Диаграммы по всему результату:** диаграммы считаются по всем строкам результата, а не только по загруженным в таблицу. В движках SQL группировка выполняется на сервере, в ячейках DataFrame SQL блокнота её делает DuckDB, а в остальных движках — DBine.
- **Больше типов диаграмм:** гистограмма, тепловая карта, ящик с усами (с усами и выбросами), столбцы с линиями и KPI (сумма по всему результату).
- **Несколько диаграмм в ячейке блокнота:** ячейка блокнота может показывать несколько диаграмм своего результата и запоминает, какой источник использует её карта.
- **Диаграммы в экспорте блокнотов:** блокноты, экспортированные в HTML или Markdown, включают диаграммы в виде изображений.
- **Объединение результатов из разных баз данных в блокноте:** результат каждой ячейки — это DataFrame с именем ячейки (оно показано в заголовке и редактируется), а ячейка **DataFrame SQL** запрашивает и объединяет расположенные выше DataFrame как таблицы с помощью SQL DuckDB и без подключения, так что одна ячейка может объединить результат PostgreSQL с результатами SQL Server и MongoDB. Она работает в базе DuckDB в памяти, которая не может записывать файлы и обращаться к сети, и удаляется при закрытии блокнота; строки каждого источника берутся из его выполнения в этом сеансе или из его запроса, выполненного заново, только для чтения, на его собственном подключении (до 1 000 000 строк на DataFrame, в разделе **Настройки › Блокноты**).
- **Блокноты как отчёты по расписанию:** запланированная задача может выполнить блокнот при закрытом DBine (**Выполнить блокнот**), сохранить выполненную копию и экспортировать её в HTML или Markdown, а следующий шаг **Отправить письмо** может прикрепить её или отправить HTML-экспорт в теле письма. Без присмотра ничего не спрашивается: читаются только файлы с **Всегда разрешать** для этого блокнота, на средах, требующих подтверждения, выполнение идёт только при явном разрешении шага, а ячейки, изменяющие данные, входят в одобрение задачи. Экспорт по расписанию включает таблицы; диаграммы включаются при экспорте из приложения.
- **Локальные файлы в ячейках DataFrame SQL:** ячейка DataFrame SQL может читать файлы CSV, Parquet, JSON или NDJSON и Excel на вашем компьютере с помощью `read_csv`, `read_parquet`, `read_json` и `read_xlsx`, включая шаблоны вроде `data/*.csv` и списки файлов, географические файлы (GeoJSON, Shapefile с сопутствующими файлами, GeoPackage, KML, GPX, FlatGeobuf) с помощью `st_read`, а также таблицы из файлов баз данных SQLite и DuckDB с помощью `sqlite_scan` и `read_duckdb`; каждый из них становится DataFrame, который можно объединять с результатами ячеек любого движка; геометрии по-прежнему работают с пространственными функциями вроде `ST_Contains` и отображаются на карте. Файлы только читаются, но никогда не записываются. Перед первым чтением файла блокнот спрашивает: разрешить на этот запуск, всегда для этого блокнота на этом компьютере (шаблон охватывает и новые файлы) или запретить; учётные данные, ключи, история оболочки и системные файлы не читаются никогда. Если содержимое файла изменилось с прошлого запуска, результат сообщает об этом. В разделе Настройки › Блокноты перечислены файлы, которые может читать каждый блокнот, и их можно удалить. Те же функции чтения читают файлы из интернета (`https://`) и из Amazon S3, Google Cloud Storage и Azure Blob Storage (`s3://`, `gs://`, `az://`, `abfss://`, с шаблонами вроде `s3://bucket/2026/*.parquet`) с тем же одобрением, которое сначала показывает сервер; DBine сам скачивает их в закрытую временную папку, удаляемую после чтения, используя вход AWS, Google Cloud или Azure этого компьютера (профиль AWS можно выбрать в Настройки › Блокноты), и никогда не обращается к локальным или частным сетевым адресам, не переходит по перенаправлениям на другие серверы и не принимает учётные данные в URL. GeoPackage, открытый в другой программе, теперь включает изменения, ещё находящиеся в его `-wal`.
- **Экспорт блокнота как блокнота Python:** **Экспорт › Блокнот Python (.ipynb)** записывает блокнот Jupyter, воспроизводящий его: по одному движку SQLAlchemy (или собственному клиенту Python движка, например pymongo или redis) на подключение, каждая ячейка запроса читается в DataFrame pandas с именем ячейки, ячейки DataFrame SQL выполняются с DuckDB над этими DataFrame, а текстовые ячейки становятся Markdown. Пароли и токены никогда не экспортируются: код читает их из переменных окружения, которые первая ячейка перечисляет вместе с пакетами для установки. Результаты не включаются, если вы не выберете включение предпросмотров.
- **Запись DataFrame в таблицу из блокнота:** **ячейка записи** (добавляется под любой ячейкой через **Записать в таблицу…**) записывает весь результат ячейки в таблицу SQL Server, PostgreSQL, MySQL, MariaDB, Oracle, SQLite, DuckDB, MongoDB и других: вставка, обновление по ключу, вставка или обновление либо замена содержимого таблицы, с сопоставлением столбцов, предпросмотром и при желании новой таблицей. Каждая запись сначала спрашивает, показывая куда, как и сколько строк (на производственных подключениях нужно ввести имя таблицы), выполняется в одной транзакции там, где движок их поддерживает, а подключения только для чтения никогда не записываются. В запланированной задаче ячейка записи выполняется только если шаг разрешает именно эту ячейку, таблицу и режим.
- **Параметры блокнота:** блокнот может определять параметры (текст, число, дата, дата и время, логическое значение или фиксированный список, со значением по умолчанию), которые его ячейки используют как `{{name}}`; при запуске запрашиваются недостающие значения, каждое значение передаётся в базу данных как данные (привязывается драйвером или экранируется по правилам движка), а каждый результат показывает значения, которые его породили.
- **Ещё пять языков:** DBine и его приложение для телефона теперь говорят по-немецки, по-русски, на упрощённом китайском, японском и корейском, помимо испанского, английского, португальского, французского и итальянского; язык следует за языком вашей системы, и загружается только используемый.

### Улучшения
- **Подпись в macOS:** приложение для macOS подписано Apple Developer ID и нотаризовано Apple, поэтому открывается без предупреждения «не удаётся проверить разработчика» и без команд в терминале. При первом открытии подписанной версии macOS один раз спросит, может ли DBine использовать свой ключ в связке ключей: выберите **Всегда разрешать**.
- **Облачный вход доверяет только сертификату экземпляра:** подключения, входящие через AWS IAM, Google Cloud IAM или Microsoft Entra, а также подключения Cloud SQL и AlloyDB с файлом CA экземпляра теперь принимают только этот CA (или пакет RDS от Amazon), а не любой публичный сертификат, прежде чем отправить токен или пароль. Сервер, запрашивающий пароль в открытом виде при включённом **Доверять сертификату сервера**, теперь получает отказ вместо пароля.
- **Подпись в Windows:** установщик Windows и приложение подписаны сертификатом подписи кода, поэтому Windows показывает издателя DBine вместо «Неизвестный издатель».

### Исправления
- **Монитор сервера:** его показатели, таблицы и примечания переведены во всех движках, а не показывают часть подписей на испанском.
- **ИИ-ассистент и оптимизатор:** инструкции для модели составлены на языке интерфейса, поэтому локальная модель отвечает на этом языке, а не на испанском. Строка о том, что было отправлено модели, тоже переведена.
